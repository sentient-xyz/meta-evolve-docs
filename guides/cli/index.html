    Command line¶

    Run two improvement experiments, compare their results, and reopen their recorded history from the terminal. The walkthrough uses deterministic local examples and requires no model credentials.

    Run and compare¶

    From a checkout, install the package with uv sync --locked. This offline example needs no credentials. Its artifact is a number; the proposer changes that number, the evaluator measures distance from a fixed target, and only search changes between the two declarations.

    The first factory fixes the target at 12, starts at 0, and permits eight successor attempts. Greedy keeps the best measured parent; BestOfN always proposes from the seed. Feedback is omitted and named randomness uses seed 35.

    Complete experiment modules

    experiment.py:

    """A CLI experiment module: one ``experiment()`` factory and nothing else.

This is the whole convention. The module defines its components and returns a
typed ``meta.Experiment``; importing it starts no run, opens no storage,
and prints nothing. The command line supplies the infrastructure it owns:

    meta-evolve run examples/operations/command_line/experiment.py --storage ./store

``examples/learn/number_search/main.py`` is the same search written as a script.
A script is not an experiment module: importing one runs it. That difference
is exactly what this file exists to show.
"""

from __future__ import annotations

import meta_evolve as meta


TARGET = 12
MOVES = (-2, 1, 5)


def propose(parent: object, *, context: object) -> object:
    """Take one random declared move away from the parent."""

    return parent + context.rng.choice(MOVES)


def score(candidate: object) -> float:
    """Higher is better; reaching the target scores the maximum 0."""

    return -abs(candidate - TARGET)


def experiment() -> meta.Experiment:
    """The factory the command line calls. Plain callables, so this module
    runs under the default ``--mode local``. See ``resumable.py`` for the
    registered-component shape ``--mode durable-local`` requires."""

    return meta.Experiment(
        task=meta.Task(
            evaluator=score,
            objectives=(meta.Maximize("score", satisfy=0),),
            budget=meta.Budget(evaluations=9, trials=8),
        ),
        seed=0,
        proposer=propose,
        search=meta.Greedy(max_trials=8),
        random_seed=35,
    )

    best_of_n.py (keep beside experiment.py):

    """The comparison variant: the same experiment under a different policy.

``meta.Run.compare`` refuses two runs that do not declare the same task,
initial artifact, budget, and proposer, so a comparable variant has to reuse
them rather than restate them. This module therefore uses
``dataclasses.replace()`` on ``experiment.py``'s declaration to change exactly
one field — the search policy:

    meta-evolve run examples/operations/command_line/best_of_n.py --storage ./store
    meta-evolve compare <greedy-run-id> <best-of-n-run-id> --storage ./store

The sibling import works because the command line appends an experiment
module's own directory to ``sys.path``.
"""

from __future__ import annotations

from dataclasses import replace

import meta_evolve as meta
from experiment import experiment as greedy_experiment


def experiment() -> meta.Experiment:
    """Greedy hill climbing swapped for independent best-of-N attempts."""

    return replace(greedy_experiment(), search=meta.BestOfN(max_trials=8))

    Start with two runs in one durable store:

    uv run meta-evolve run examples/operations/command_line/experiment.py --storage ./store
# Selected output: score 0; evaluations 6; lineage 0 -> 1 -> 2 -> 7 -> 12
uv run meta-evolve run examples/operations/command_line/best_of_n.py --storage ./store
# Selected output: score -7; evaluations 9; lineage 0 -> 5
uv run meta-evolve list --storage ./store

    run imports one side-effect-free experiment() factory returning meta.Experiment and prints the new run's summary. list returns the stored run IDs. Use those IDs next:

    uv run meta-evolve inspect <greedy-run-id> --storage ./store
uv run meta-evolve compare <greedy-run-id> <best-of-n-run-id> --storage ./store

    inspect reports lifecycle, rankability, declarations, attempts, evidence, and decisions, including typed failures. compare first requires a successful measurement from each run, then checks that the task, initial artifact, budget, and proposer declarations are compatible. It reports both runs and their winner or exact tie. The BestOfN module reuses the first module's declarations so only search behavior changes.

    For an optional server-rendered view over the same read-only public queries:

    uv sync --extra browser
uv run meta-evolve ui --storage ./store --port 8000

    The local browser guide documents its fixed loopback scope, exact-version caches, rendering exclusions, and absence of authentication.

    The canonical examples/operations/command_line/ walkthrough pins this entire transcript through subprocess tests.

    Reports and exit status¶

    run and resume print the summary to stdout, including lifecycle, rankability, stop reason, and recorded costs. An absent score or winning lineage prints none. A measured zero is still a score; retaining the seed still ranks. Wall-clock measurements remain omitted from stable text.

    Outcome stdout stderr Exit
    Rankable run or resume Summary Empty 0
    Unrankable run or resume Summary with absent score and retained costs Empty 1
    inspect of any valid history, including pending seed evaluation Detailed report Empty 0
    Compatible rankable compare Comparison Empty 0
    Missing/corrupt run, refused comparison, or inadmissible execution Empty Typed error 1
    Usage or experiment-module error Empty Error 2

    Unexpected defects keep their traceback. The migration guide explains the changed failure report; commands and factory declarations keep their existing inputs.

    Resume is a declared capability¶

    Create a reconstructable run, then resume it:

    uv run meta-evolve run examples/operations/command_line/resumable.py \
    --storage ./store --mode durable-local
uv run meta-evolve resume <run-id> \
    --module examples/operations/command_line/resumable.py --storage ./store
    Complete resumable module 
    """The experiment-module shape ``--mode durable-local`` requires.

Same convention as ``experiment.py`` — one ``experiment()`` factory, no
import-time side effects — but the factory registers its components and
returns the registry, so the run is recorded resumable:

    meta-evolve run examples/operations/command_line/resumable.py \\
        --storage ./store --mode durable-local
    meta-evolve resume <run-id> \\
        --module examples/operations/command_line/resumable.py --storage ./store

Two modules rather than one because the library requires different component
shapes for the two modes: local mode drives live callables, durable-local
drives registered, source-digestible module-level functions so a resumed run
can verify it is replaying the code that was recorded. The command line does
not choose between them and does not check either — it passes ``--mode``
through and lets ``meta.run`` enforce its own contract.
"""

from __future__ import annotations

import meta_evolve as meta


TARGET = 6


def climb(parent: object, *, context: object) -> object:
    """Deterministic and retry-safe: the same parent always yields the same
    child, so replaying it during recovery reproduces the identical candidate.
    ``context`` is unused because this climb has no randomness in it."""

    return parent + 1


def score(candidate: object) -> float:
    """Higher is better; the target itself is the ceiling."""

    return -abs(float(candidate) - TARGET)


def experiment() -> meta.Experiment:
    """Register the components and hand back the typed declaration plus the
    registry ``meta.run`` and ``meta.resume`` both resolve against."""

    registry = meta.Registry()
    proposer = registry.register_proposer(
        "example:climb", "1", climb, deterministic=True, retry_safe=True
    )
    evaluator = registry.register_evaluator(
        "example:score",
        "1",
        score,
        deterministic=True,
        retry_safe=True,
        configuration={"target": TARGET},
    )
    return meta.Experiment(
        task=meta.Task(evaluator=evaluator, budget=meta.Budget(evaluations=8)),
        seed=0,
        proposer=proposer,
        search=meta.Greedy(max_trials=8),
        registry=registry,
    )

    The module registers source-digestible proposer and evaluator functions. On resume, its factory rebuilds the registry and the library verifies the recorded component identities. A local run may use durable storage and remains listable and inspectable, but it is not resumable.

    The command line adds no capability rules. It passes --mode to meta.run and lets meta.resume accept or refuse the recorded run. The programming model owns the five report-verb mappings, factory convention, modes, and exit codes.

    For a real interrupted-process workflow, continue with the examples/operations/durable_operations/ walkthrough.

    Change and predict¶

    Run the two commands above, then inspect the IDs printed by list. Compare their parent choices as well as their best scores. These commands report recorded results; a different search policy does not guarantee a higher score. Try resuming the local run: expect CapabilityError. The registered durable-local example can resume; repeating resume after completion adds no work.

    Command reference¶

    The CLI is a thin translation over the public run and durability contracts.

    meta-evolve run MODULE --storage STORAGE [--mode local|durable-local|distributed]
                       [--workers N | --listen ADDR --key-file PATH]
                       [--lease-seconds S]
meta-evolve list --storage STORAGE
meta-evolve inspect RUN_ID --storage STORAGE
meta-evolve resume RUN_ID --module MODULE --storage STORAGE
                          [--workers N | --listen ADDR --key-file PATH]
                          [--lease-seconds S]
meta-evolve compare LEFT_RUN_ID RIGHT_RUN_ID --storage STORAGE
meta-evolve ui --storage STORAGE [--port PORT] [--module MODULE]
meta-evolve worker --module MODULE --connect ADDR --key-file PATH --worker-id ID

    Each verb makes one public call:

    Verb Public call Result
    run meta.run(...) Run ID and summary
    list storage.runs() Reachable content-derived run IDs
    inspect run.inspect() Overview, declaration, trials, decisions
    resume meta.resume(...) Verified missing durable-local or distributed work
    compare run.compare(other) Compatible comparison and winner

    worker is the second long-running exception, beside ui: it makes no run of its own, and serves one that is already listening.

    The module's side-effect-free experiment() factory returns Experiment. Dictionary factories remain functional under the pre-1.0 release policy, but each load emits DeprecationWarning naming the module and factory and asking for meta.Experiment(...). Unknown keys and the execution-owned storage, mode, and call-level budget remain usage errors; those overlays belong to the command line and run().

    Failures in the RunError hierarchy become concise CLI errors without tracebacks. Unknown arguments, invalid factories, missing runs, capability gaps, and incompatible comparisons fail closed.

    The CLI does not add an artifact history, registry, evaluator, or promotion authority of its own. Git may be ingress or egress for source, but durable Meta-Evolve artifacts and transitions remain the experiment record. Inspection includes failures, artifact occurrence identity and digest, evidence, decision rationale, and named randomness. Measured wall-clock values remain omitted so equivalent deterministic runs produce byte-identical output.

    Worker processes¶

    A distributed run executes inline by default. There are two ways to select worker processes.

    The dispatcher can spawn its own:

    uv run meta-evolve run examples/operations/command_line/best_of_n.py \
  --storage ./store --mode distributed --workers 4

    Or it can listen, and an operator starts workers wherever there is capacity:

    uv run meta-evolve run examples/operations/command_line/best_of_n.py \
  --storage ./store --mode distributed --listen 127.0.0.1:9000 \
  --key-file ./worker.key

uv run meta-evolve worker --module examples/operations/command_line/best_of_n.py \
  --connect 127.0.0.1:9000 --key-file ./worker.key --worker-id shed-1

    What each option means:

    • --workers N spawns N children of this dispatcher. They exit with it: each one watches the pipe its parent holds, so even a SIGKILLed dispatcher leaves none behind. They are not replaced if they die, and a run whose workers have all died is refused by name so it can be resumed.
    • --listen ADDR --key-file PATH opens a port instead. The key file is created private (0600) if it is absent and REUSED if it is present, so restarting a dispatcher does not lock out the workers that hold it. A run that is listening WAITS when no worker is connected rather than failing.
    • --lease-seconds S is how long a work lease lasts, at least 10. A worker's call is renewed while it runs; if a lease is lost anyway, that attempt is retried and at most one completion is ever accepted.
    • --worker-id ID names a worker. worker- is reserved for the ids a dispatcher mints for the children it spawns, and starting a second process with an id that is already connected is refused rather than taking the first one's place, including when both handshakes overlap.

    Both ends authenticate with the key file before anything about the run crosses the connection, and a worker is admitted only if it runs the same build and resolves the same components the run recorded. The key authenticates; it does not encrypt. Multi-host use is documented and untested: it needs TLS, which Meta-Evolve does not provide. Keep the address on a loopback or a trusted network.

    Resuming is the same command with the same flags:

    uv run meta-evolve resume RUN_ID --module examples/operations/command_line/best_of_n.py \
  --storage ./store --workers 4

    A dispatcher that died mid-run leaves its work claimable again. An external worker retains a completed result even if its first write fails, reconnects, and resubmits it. A result already committed receives the recorded acknowledgment; an expired or superseded attempt receives a stale answer. If the listening address now serves a different run while the worker holds an unanswered result, the worker exits with a refusal naming both runs. It never submits one run's result to another.

    Read-only local browser¶

    ui is the one long-running lifecycle exception to the five deterministic report verbs. Install it explicitly and serve an existing durable store:

    uv sync --extra browser
meta-evolve ui --storage ./store --port 8000

    The host is fixed to 127.0.0.1, the worker count is fixed to one, and valid ports are 1..65535. There is no host or worker override. The command owns no domain query or HTML logic: it conditionally imports and delegates to the browser server. Uvicorn retains its operational logging. Missing browser dependencies give installation guidance and exit 2; store-open and schema failures remain typed CLI domain failures and exit 1 before a socket binds.

    The browser is read-only, local, and unauthenticated. Loopback scope is not a remote-safety or authentication claim. See the browser guide for the replay, cache, polling, and rendering boundaries.

    For a run using a custom artifact codec, ui --module MODULE loads the same side-effect-free experiment() convention and passes only its registry to the read-only browser. Browser dependencies are imported first. No proposer, evaluator, policy, session, execution, or mutation surface is invoked. Missing custom codecs remain actionable 422 capability states.
