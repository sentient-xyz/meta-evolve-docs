    Runs and results¶

    For an introduction to what each object needs and how you use it, follow the parser through Task, Experiment, Session, and Run. This reference covers execution details, search presets, and result queries.

    meta.improve() is the smallest bounded local path. It evaluates the seed, asks the proposer for successors, evaluates each valid successor independently, and uses greedy search to decide where work goes next.

    import meta_evolve as meta

items = ("outline", "draft", "review")

def complete_one(completed):
    return (*completed, items[len(completed)])

result = meta.improve(
    seed=(),
    proposer=complete_one,
    evaluator=len,
    trials=3,
)

    That call lowers exactly to:

    experiment = meta.Experiment(
    task=meta.Task(evaluator=len),
    seed=(),
    proposer=complete_one,
    search=meta.Greedy(max_trials=3),
)
result = meta.run(experiment)

    Use the expansion for custom artifacts, objectives, satisfaction thresholds, task budgets, search, context, experience, execution mode, or registry components. Experiment owns declaration fields; storage=, mode=, and a narrowing budget= remain call-level execution overlays. The declaration-keyword run() form remains supported under the pre-1.0 release policy and is not the taught path.

    improve(storage=Storage.durable(...)) persists local history, but the façade does not claim durable-local reconstruction or resumability. Those require an explicit Experiment, registered reconstructible components, and run(..., mode="durable-local").

    Pace one decision at a time¶

    Session is the active execution handle beneath run(). Start it with an experiment when you need to inspect each completed decision. With the checklist experiment above:

    with meta.Session.start(experiment) as session:
    first = session.step()
    print(session.run.best().value)
    while not session.stopped:
        session.step()
result = session.run
print(result.best().value)
# Output:
# ('outline',)
# ('outline', 'draft', 'review')

    The seed is already bootstrapped when start() returns. A successful step() returns one immutable trial, archive, or stop decision only after its authorized work is complete. Manual steps and later iteration continue without repeating a decision. A newly committed stop is yielded once; repeated terminal step() calls return the same cached stop view without writes.

    Leaving the context closes only that handle's execution scope. Its stable session.run and session.stopped remain queryable, and caller-owned storage stays open. Exit does not invent a stop for an incomplete run.

    The seed is an evaluated baseline recorded as a bootstrap trial. Proposal allowances count subsequent attempts. Every successor proposal has its own trial and either an artifact plus evaluation or a typed failure.

    Search presets¶

    For a complete notebook example, Choose what to try next compares a handwritten Greedy loop with recorded Greedy and TreeSearch runs. It follows their parent choices under the same allowance, then saves and reopens the history. The score table is constructed to illustrate the policies; all setup is on that page.

    Search changes allocation, not proposer or evaluator semantics:

    • Greedy expands the current best successful artifact.
    • BestOfN samples independent successors from the seed. Its cohort_width declares how many trial decisions one generation commits together; the default of one is the sequential decision, and a wider declaration raises CapabilityError on the synchronous path until concurrent execution ships. The width reaches run identity, so a wide declaration is a different run from a narrow one.
    • BestOfK samples k successors from the current incumbent, then reselects the global incumbent so later cohorts can compose. It interpolates the two presets above: k=1 reproduces Greedy's chain, and any k at or above max_trials never completes a cohort and so reproduces BestOfN's star. Because a cohort advances the frontier by at most one level, k also bounds how far a run can travel from the seed — depth <= ceil(max_trials / k). That is a ceiling, not a guarantee: the frontier only advances when a child actually beats the frozen parent.
    • Population retains a bounded population and uses deterministic tournament selection.
    • Specialists (from meta_evolve.policies import Specialists) retains the best successful occurrence for each of a configured tuple of metrics and expands a uniformly sampled metric's owner. It is GEPA-style per-key retention, not a Pareto archive, and is namespaced rather than root-exported.
    • TreeSearch (from meta_evolve.policies import TreeSearch) reconstructs a mutation tree from durable history, widens a node while child_count < ceil(sqrt(node_visits)), and otherwise descends by normalized best-descendant UCT. It is namespaced rather than root-exported.

    All presets consume the same declared Budget and expose the same Run queries.

    Inheriting the trial limit from the budget¶

    Greedy, BestOfN, Population, Specialists, and TreeSearch accept omitted or None max_trials. Both take the effective finite Budget.trials instead of repeating the number, including for Experiment(search=None).

    This complete example starts at zero, proposes adding one, and scores each number by its value. Greedy keeps expanding the highest-scoring number. The budget allows nine attempts and ten evaluations, including the seed.

    import meta_evolve as meta

def increment(number):
    return number + 1

def score(number):
    return number

experiment = meta.Experiment(
    task=meta.Task(
        evaluator=score,
        objectives=(meta.Maximize("score"),),
        budget=meta.Budget(evaluations=10, trials=9),
    ),
    seed=0,
    proposer=increment,
    search=meta.Greedy(),  # resolves to 9
)
result = meta.run(experiment)
print(result.best().value)
print((result.usage().trials, result.usage().evaluations))
# Output:
# 9
# (9, 10)

    Without a finite trial ceiling, these presets use a finite fallback: 20 for Greedy, BestOfN, Population, and Specialists; 100 for TreeSearch. Explicit integers retain voluntary stops. BestOfK, improve(trials=20), and custom or functional search keep their own limits. See migration to preserve an older declaration's work amount.

    The effective budget composes Task.budget with a partial run-level restriction. Resolution happens once, while the preset is bound at the start of the run, and the resolved integer — not None — is what lands in SearchSpec, in the run identity, and in the durable record. Replaying or resuming that record reuses the recorded integer, so the limit cannot drift when a later process supplies a different budget.

    Two edges are worth naming:

    • With no finite trial ceiling, even repeated failed proposals stop at the preset's fallback. Token/evaluation ceilings do not alone bound failed proposals that report no resources.
    • max_trials=0, whether written directly or inherited from Budget(trials=0), is seed-only: the seed is evaluated, no successor is attempted, and the run stops with trial_limit_reached.

    A preset limit narrows voluntary work; it never widens external authority. An explicit limit above the budget still stops at the budget, with stop reason budget_exhausted rather than trial_limit_reached. Trials count attempts, including proposer failures, so inheriting trials=9 allows at most nine attempts. A satisfaction threshold or a tighter budget in another dimension can stop the run earlier.

    Functional incumbent refinement¶

    Use @search when a bounded custom policy only needs to choose between the seed and current incumbent:

    @meta.search(max_trials=20)
def incumbent_refinement(search):
    """Expand the best measured artifact."""
    return search.expand(search.incumbent or search.seed)

    The decorated value is an ordinary bindable search program and can be placed directly on Experiment.search. The callback receives opaque occurrence handles, immutable search.configuration, search.expand(parent), and search.stop(reason)—not SearchState, budgets, proposer references, trial records, or randomness. Additional behavior-affecting values are declared on the decorator, for example @meta.search(max_trials=20, patience=3), and are persisted in SearchSpec and included in run identity. Captured closure values are rejected with guidance to declare configuration and keep helpers at module scope.

    The callback name is humanized in recorded decisions, and the first cleaned docstring line becomes its summary. Envelope stops such as objective satisfaction, the trial limit, and budget exhaustion use the same narration. Unsupported returns fail before proposer work and name the supported expand() and stop() actions.

    Memory and durable storage both work in ordinary local mode. Reconstructible durable-local execution is the existing full extension workflow: register a module-level policy factory under the decorated policy reference, alongside the proposer and evaluator. The façade performs no ambient or automatic registration. Use SearchProgram.next() when a policy needs multiple parents, archive updates, populations, or other kernel decisions.

    Query the result¶

    • best() decodes the selected artifact value.
    • best_trial() returns its TrialView.
    • trials() returns every seed and successor outcome in logical order -- by the trial's logical step, never the order results happened to arrive. Exact ties in ranking fall to that same order.
    • inspect() returns one winner-independent RunInspection from one validated replay.
    • lineage() follows the selected artifact's causal parents.
    • summary() returns lifecycle, rankability, optional score, recorded usage, experience use, and winning lineage from one validated snapshot.
    • compare(other) requires a successful measurement on each side, then checks declaration compatibility before naming a winner or exact tie.

    Run is inspectable even when no evaluation succeeds. summary() then returns primary_score=None and empty winning_lineage; best() raises the typed NoSuccessfulEvaluation rather than inventing a low score. The seed participates in selection, so failed successors alone do not make a run unrankable. See the summary contract and migration guide.

    inspect() is the complete read boundary for authors and presentation code. Its overview separates lifecycle (complete or incomplete) from rankability (rankable or unrankable), so failed evaluations and recoverable prefixes do not become synthetic run states or scores. declaration retains the resolved search (including its resolved integer trial limit), component roles, budgets, capabilities, context, experience, and root random seed. Occurrence-ordered trials, typed decisions, evidence, and artifacts expose the complete history without exposing events or replay projections. The bootstrap seed is a trial at logical step zero, never a search decision.

    Decision inspection is a real sum type: TrialDecisionView names selected parents and an optional completed trial, ArchiveDecisionView reports admission, eviction, and resulting membership, and StopDecisionView reports the terminal reason. Every variant carries its durable identity, logical step, non-optional rationale, and named randomness.

    Artifact values¶

    Plain Python values use the default codec. Text, SourceTree, and SkillSet provide shipped typed domains. Every accepted successor is frozen before commitment and records distinct occurrence identity plus parent lineage.

    Comparison¶

    Comparison refuses incompatible task, evaluator, artifact, model/environment, or relevant declaration identity through RunsNotComparable. Random seed, context, and experience differences remain visible compatibility flags when the comparison contract permits them. A comparison is measured evidence, never a promotion.
