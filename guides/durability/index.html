    Durability¶

    For a complete notebook walkthrough, start with Save and reopen a run.

    Storage composes artifact and event storage. In-memory storage is isolated to the process. Durable storage uses a verified filesystem artifact store plus an append-only SQLite event stream.

    import meta_evolve as meta

storage = meta.Storage.durable(".meta-evolve/example")

    Store¶

    Pass durable storage to meta.run() to preserve committed artifacts, evidence, decisions, lineage, usage, and failures. mode="durable-local" additionally requires registered reconstructible components and their verified manifests. Validation happens before the first event is written.

    Reopen¶

    open_run opens existing history for a with block:

    with meta.open_run(".meta-evolve/example") as reopened:
    snapshot = reopened.summary()

print(snapshot)

    Pass the directory used for Storage.durable(). Without run_id=, it opens the only recorded run. An empty store raises RunNotFound; several runs raise RunSelectionRequired with a run_ids tuple of available IDs. Choose explicitly with meta.open_run(path, run_id=saved_id), using a RunId or its saved string. IDs are listed lexically; their order does not establish which run is newest. An explicit missing ID never substitutes another run.

    Calling open_run() creates a context manager. Entry validates the arguments, opens storage, and validates the selected history before yielding Run, including incomplete and unsuccessful runs. Storage closes on success or error. Capture summaries, inspections, usage, and selected values inside the block; those results remain usable afterward. A subsequent query on the live Run still requires open storage and surfaces a store error after close.

    Reopen performs no proposal or evaluation and never resumes work. Local callable and SDK histories can be durable and inspectable even when their live components cannot be rebuilt. For custom artifacts, supply registry= with reconstructed codecs to decode values. Without the required codec, entry and usage() still work, while a decoded query such as best() raises CapabilityError naming the missing codec. Supplied codecs are trusted Python extensions invoked by decoded queries, not by opening the run.

    For explicit storage ownership, keep using Run directly:

    with meta.Storage.read_only(".meta-evolve/example") as storage:
    version = storage.run_version(run_id)
    inspection = meta.Run(run_id, storage).inspect()

    is_durable and is_read_only answer different questions. The first says committed facts live on durable media; the second says this handle cannot commit. Storage.durable(...) reports True, False, while Storage.read_only(...) reports True, True. Artifact, blob, event, and unit-of-work writes all raise CapabilityError. Passing the handle to run(), improve(), or resume() is rejected before a codec, registry component, proposer, evaluator, provider, or subprocess runs.

    run_version(run_id) is the maximum committed event sequence. It returns 0 for a well-formed id with no events and uses a new deferred transaction on each call, so a long-lived reader observes successive atomic commits from a WAL writer. It is deliberately a cheap polling query, not a full integrity check. An open_run() block also permits fresh reads: it selects the identity once, but does not freeze subsequent queries to the entry-time history. Run(run_id, storage).inspect() performs authoritative loading and still raises RunNotFound when that run is required but absent.

    The optional local run browser owns one long-lived read-only handle on one dedicated thread. It calls runs() to discover additions, polls exact versions before replay, and never polls a cached completed run again. Its bounded caches are disposable observations; append-only storage and validated replay remain authoritative.

    Read-only open requires an existing current store. It uses SQLite mode=ro plus query_only, and never creates a directory, changes journal settings, executes DDL, stamps a schema, or migrates. For an older or unstamped store, close readers and reopen it once with writable Storage.durable(...), then use Storage.read_only(...) again. Future schemas raise SchemaVersionRejected, malformed current schemas raise DurableCorruption, and missing or inaccessible database/filesystem/WAL state raises DurableStoreError with the underlying cause.

    Read-only means no changes to committed history and no framework writes or migration. SQLite can create or maintain -wal and -shm sidecars even through a read-only connection; see its WAL documentation. The reader preserves live WAL visibility and does not use SQLite's immutable mode. It never creates a missing store directory or repairs an incomplete one.

    Resume¶

    resume verifies manifests, declarations, store integrity, and the recovery frontier before doing missing work. It retains the same run ID and never re-executes a committed operation. A non-resumable local history raises CapabilityError.

    Registered proposer verification includes the framework's invocation source. The explicit keyword-context cutover changes those manifests even for unchanged parent-only callbacks. Older histories remain readable; continuation requires their matching implementation. See the callback migration guide.

    Use Session.resume to pace that same recovery:

    with meta.Session.resume(run_id, storage=storage, registry=registry) as session:
    for decision in session:
        observe(decision)
result = session.run

    A distributed run resumes through the same call and then drive(), because it is scheduled rather than stepped — iterating its decisions raises. resume() makes that choice for you; hold the session yourself and you make it:

    with meta.Session.resume(run_id, storage=storage, registry=registry) as session:
    session.drive()

    drive(lease_seconds=60) renews each call's lease while it runs; the duration must be at least 10 seconds. A failed renewal ends the drive, but Python cannot cancel the component's helper thread. Resume may execute that work again while the old call finishes. Leases and dispatcher epochs prevent accepting a stale result; this does not guarantee that external side effects happen only once.

    Preparation validates and classifies the committed frontier but does not finish pending work. The first step() either completes the already committed trial or evaluation, or records and completes one new decision. Resuming an already stopped run iterates zero times; an explicit terminal step() returns the existing stop view without changing events or artifacts.

    Complete registered-resume example¶

    Run this as a Python file with meta_evolve installed. It compares saving a local run with reconstructing registered components for resume. The temporary stores are for this demonstration only; retain a persistent directory for real work. Omitting session.step() leaves both revisions for resume to perform.

    resume_checklist.py · complete example
    """Registered resume demonstration, moved from the beginner persistence lesson."""

from pathlib import Path
from tempfile import TemporaryDirectory
import meta_evolve as meta


def add_item(items):
    return (*items, ("outline", "draft")[len(items)])


def score(items):
    return len(items)


def declaration():
    registry = meta.Registry()
    proposer = registry.register_proposer(
        "checklist:add", "1", add_item, deterministic=True, retry_safe=True,
    )
    evaluator = registry.register_evaluator(
        "checklist:score", "1", score, deterministic=True, retry_safe=True,
    )
    return meta.Experiment(
        seed=(), proposer=proposer, task=meta.Task(evaluator=evaluator),
        search=meta.Greedy(max_trials=2), registry=registry,
    )


with TemporaryDirectory() as directory:
    root = Path(directory)
    with meta.Storage.durable(root / "saved") as storage:
        result = meta.improve(seed=(), proposer=add_item, evaluator=score,
                              trials=2, storage=storage)
        saved_id = result.id
    with meta.Storage.read_only(root / "saved") as storage:
        reopened = meta.Run(saved_id, storage)
        print("Reopened:", reopened.best().value)

    with meta.Storage.durable(root / "continued") as storage:
        with meta.Session.start(declaration(), storage=storage, mode="durable-local") as session:
            session.step()  # Finish one revision, leaving one to perform.
            run_id = session.run.id
            print("Before resume:", session.run.usage().trials)
    with meta.Storage.durable(root / "continued") as storage:
        resumed = meta.resume(run_id, storage=storage, registry=declaration().registry)
        print("After resume:", resumed.usage().trials)
        print("Selected:", resumed.best().value)
# Output:
# Reopened: ('outline', 'draft')
# Before resume: 1
# After resume: 2
# Selected: ('outline', 'draft')

    Compare¶

    Reopened completed runs use the same comparison contract as live results. Declaration mismatches raise RunsNotComparable before ranking.

    Replay and reproducibility¶

    Replay is a pure fold over immutable transitions and artifacts. It reconstructs logical decisions, projections, context selection, access audits, and usage without calling external systems. Named random streams reproduce deterministic local choices. Provider output is not promised to regenerate byte-for-byte; the durable guarantee is the exact committed transcript and declarations.

    Usage records retain unknown billed spend as explicit null; omitted spend still means the historical default of zero. Existing zero and integer records keep their canonical bytes. Readers predating nullable spend cannot read these new unknown values. Inspection and replay reuse cost evidence without rerunning user callbacks; recovery may repeat external work whose outcome never committed.

    Corrupt bytes, unknown schemas, gaps, mismatched IDs, and incomplete atomic batches fail explicitly rather than falling back to a partial interpretation.

    Open a store from an earlier version¶

    The current durable store schema adds the work and lease tables that distributed mode uses. No recorded event byte changes, and the upgrade is one-way: an earlier release refuses a migrated store as a future schema. A store an older release migrated from v1 has its events table rebuilt with the same rows, and one holding an event with no digest is refused as corrupt. A store written by an earlier release must be opened once with writable Storage.durable(...), which migrates it; until then Storage.read_only(...) and the run browser refuse it with SchemaVersionRejected.

    A durable-local run that uses BestOfN and was recorded by an earlier release does not resume. Its RunStarted manifest records a digest of the policy's module source. The current release changes that module, and resume compares the digest exactly, so it refuses with CapabilityError. Finish such runs before upgrading. The run id and the stream's other bytes are unchanged.

    Exact source matching also includes docstrings and other text in a hashed module. The reference refresh changes the source digests of Greedy, BestOfN, AncestorsOnly, and BestSibling, even though their execution logic is unchanged. Runs with those earlier manifests remain inspectable, but resume requires matching component source. Complete unfinished work with its matching package before upgrading; do not bypass the manifest check.

    An artifact read that meets damaged durable state -- including a committed artifact the store no longer has -- now raises DurableCorruption with the original fault on local and durable-local runs. Earlier releases stopped the same run with InvalidDecision wrapping the cause, so code that catches InvalidDecision for this case no longer sees it.

    The ordinary read failures that are still translated -- a KeyError, a timeout, anything the store answers with that is not damage -- now raise InputsUnavailable rather than InvalidDecision, so nothing reaching a caller from a parent load answers to that name any more. The two were one type and had come to mean two things: InvalidDecision is a verdict that a decision is malformed or exceeds its authority, and a distributed run ends a work item whose recorded cause names it WITHOUT retrying, because no second attempt makes an invalid decision valid. An input that could not be read is the case the retry bound exists for, and collapsing the two would have ended such an item on its first flaky read.
