    Migrate to 0.2¶

    This guide covers the integrated author API revision: improve an artifact, inspect what happened, and compose that loop into a larger procedure. The core objects remain Task, Experiment, and Run; there is no new procedure class.

    Choose the right package¶

    These changes are Shipped in the source accompanying this documentation. Package metadata remains 0.1.0 until the coordinated release is published. Use the source package supplied with these docs or the matching repository revision; an older installation with the same version string does not establish source equivalence. The project status records availability, and the release gate owns the pre-1.0 policy.

    Keep the environment and source used by unfinished old runs. Read access and permission to continue execution are separate checks.

    Review the five changes¶

    Area Earlier behavior Integrated behavior and action
    Execution budget A sparse replacement could be refused for omitting a task ceiling. Omitted/None dimensions inherit; explicit finite widening still fails. Review formerly rejected calls: they can now execute.
    Plain proposer input A second positional argument could receive framework context. Use def propose(parent, *, context). Ordinary defaults remain Python configuration.
    Run summary No successful evaluation prevented a summary. Inspect lifecycle, rankability, and an optional score. Winner selection remains strict.
    Preset allowance Bare limits were 20, or 100 for TreeSearch; None required a finite trial ceiling. Omitted/None inherits a finite effective trial ceiling, otherwise uses that finite fallback. Write the old integer to retain its voluntary limit.
    Rich component costs ProposalResult/EvaluationResult accepted Usage. Pass Resources, or inner.usage().resources for nested work. Run.usage() still includes counts.

    Ordered Task.objectives, Experiment, keyword run(...), dictionary CLI factories, existing import namespaces, and the trials/max_trials names remain. Dictionary CLI factories retain their existing deprecation warning. Plain candidate, scalar, and metric-mapping returns still need no result record.

    Update callbacks and rich returns¶

    Before, a plain callback might declare propose(parent, context) and return ProposalResult(..., usage=Usage(tokens=5)). Positional context is now refused before work. Usage is refused when constructing either rich result, including when its counts are zero; use Resources.

    This complete example combines explicit context, component costs, a task allowance, a partial execution restriction, and a report:

    import meta_evolve as meta


def revise(parent, *, context):
    return meta.ProposalResult(
        candidate=parent + context.step,
        usage=meta.Resources(tokens=5, spend_micros=None),
    )


migration_experiment = meta.Experiment(
    task=meta.Task(evaluator=float, budget=meta.Budget(trials=25, evaluations=26)),
    seed=0, proposer=revise, search=meta.Greedy(),
)
result = meta.run(migration_experiment, budget=meta.Budget(evaluations=3))
report = result.summary()
print("proposals:", result.usage().trials, "evaluations:", report.evaluation_count)
print("score:", report.primary_score, "tokens:", report.usage.tokens)
print("declared trial ceiling:", result.inspect().declaration.effective_budget.trials)
# Output:
# proposals: 2 evaluations: 3
# score: 3.0 tokens: 10
# declared trial ceiling: 25

    A callback that needs no framework input can remain def propose(parent). def propose(parent, scale=2) retains its ordinary default. Rename an optional ctx/_context parameter to keyword-only context if it was intended to receive framework input. Variadics alone do not opt in.

    Structural .propose(parent, context), runner, and patch callback interfaces keep their explicit contracts. The callback migration guide explains dispatch and signature validation in detail. Requesting context does not grant history access; feedback and experience remain explicit.

    Check how much work runs¶

    Task.budget owns the external ceiling. run(..., budget=Budget(evaluations=3)) restricts only evaluations and inherits every other dimension. Budget() retains all task ceilings. An explicitly wider finite value fails before work; zero is a real limit. Inspect result.inspect().declaration.effective_budget to see the resolved allowance. See partial budget migration for edge cases.

    With Budget(trials=25), bare Greedy() now permits 25 successor attempts, plus the seed evaluation. Greedy(max_trials=20) preserves the earlier policy limit. The same inheritance applies to BestOfN, Population, Specialists, and TreeSearch, including a partial run restriction applied before binding.

    When no finite trial ceiling exists, omitted/None falls back to 20, or 100 for TreeSearch. Explicit None therefore no longer raises for an unbounded trial budget. Failed proposals still consume attempts and reach this fallback. An explicit integer may stop earlier but cannot widen the external allowance.

    improve(trials=20) remains bounded by default; trials=None remains invalid. BestOfK, functional/custom search, and candidate-policy interpreters retain their own contracts. The search guide explains recorded limits, seed counts, targets, and stop precedence.

    Forward resources once¶

    Resources has exactly three fields: tokens, spend_micros, and wall_seconds. Trial/evaluation constructor fields are rejected. Values are immutable, validated, and additive. 0 means known free spend; None means unknown, including after addition. Report estimates in evidence. Reported elapsed work is neither wall-clock duration nor preemption.

    In a nested evaluator, replace inner.usage().without_counts with inner.usage().resources. Add the evaluator's own Resources once. Retaining or reopening the inner history does not charge it again. The executable nested example shows separate outer counts and aggregated physical costs, including unknown spend.

    Domain Usage, process results, PatchResult, and method-specific accounting records keep their existing boundary. For example, PolicyEvaluation.outer_usage is still a Usage; project .resources when returning it in an EvaluationResult. AutoResearch's example still reports outer-only usage; ACE also accounts for development, consolidation, and held-out work outside the search run. See composition.

    Handle results and commands¶

    Run.summary() reports complete/incomplete lifecycle separately from rankable/unrankable results. It includes committed costs, stop_reason, and primary_score=None with empty winning lineage when nothing ranks. A pending distributed seed can have zero evaluations and zero usage.

    Check report.primary_score is not None; a measured zero is a valid score. best(), best_trial(), default lineage(), and comparisons still require a rankable measurement. A selected seed alone does not establish improvement. Callers constructing RunSummary now supply the required keyword-only lifecycle, rankability, and stop_reason fields.

    CLI run and resume print valid unrankable summaries to stdout and exit 1, with no error on stderr. Rankable runs exit 0; inspecting valid history exits 0; usage/module errors remain exit 2. Update scripts that treated every exit 1 as stderr-only. The reporting migration guide owns the full Python and command behavior.

    Open old history deliberately¶

    Supported historical stores remain readable without running their components. The API revision changes no durable Usage schema. Older storage-schema upgrades remain the separate durability guide's responsibility.

    Resume uses recorded effective budgets and concrete policy limits; it never re-inherits today's defaults. Continuation also verifies exact component source. Registered proposer manifests now include callback invocation and adapter wiring. Preset/default and reference docstring edits can also change source digests. Expect incompatible old implementations to refuse before more work, even when reading their history succeeds.

    CandidatePolicy now reports accounting_unavailable when unknown billed spend under a monetary ceiling causes its budget stop, matching the other built-in policies. Known exhaustion remains budget_exhausted; objective and voluntary trial-limit stops keep their precedence. Historical stops retain their recorded reason. This correction changes the candidate-policy implementation digest, so runs recorded against the earlier interpreter require that source to resume.

    Finish such a run with its matching old package, registered components, and environment, or start a new experiment on the revised API. Do not rewrite stored manifests or regenerate old facts to bypass verification. The integration verification record separates historical reads, same-runtime recovery, and incompatible-source refusal.
