    Learning from experience¶

    Recorded candidates, outcomes, and evaluation evidence can help later proposals investigate a failure, preserve a successful change, or compare approaches before trying another revision.

    Experience is explicit and off by default. Recording outcomes for search and inspection does not automatically provide feedback to the proposer.

    Why experience matters¶

    Search uses evaluation results to decide which candidates deserve more work. Experience gives the proposer information that can help it decide what to change. A score can tell search which prompt performed better; the recorded responses can help a proposer understand what the weaker prompt missed.

    The same distinction applies beyond prompts. A code proposer might inspect a prior implementation and its test evidence. A harness proposer might compare recorded execution traces to understand a successful revision. These observations can suggest a change, but the next candidate still needs independent evaluation.

    What counts as experience?¶

    Feedback is one useful selection from a broader history:

    Prior information A question it can help answer
    Candidates and source revisions What was tried, and what changed?
    Measurements and recorded evaluation evidence Where did an approach succeed or fall short?
    Failed attempts and their recorded outcomes What prevented an attempt from producing a valid result?
    Lineage and comparisons between attempts Which alternatives are worth investigating together?

    Only recorded information can be retrieved. An infrastructure failure remains a typed outcome, not evidence of a low-quality candidate or an invented low score.

    Here, learning means using observations to inform a proposal. The experience mechanism does not itself train model weights or guarantee that a revision will improve. The parser feedback lesson demonstrates one narrow case: using recorded development checks to choose handwritten fixes.

    How experience reaches a proposer¶

    Recording history does not automatically expose it to a proposer. An experiment can select context before each proposal, authorize the proposer to inspect prior records during its work, or combine both approaches. Selected context is useful when the relevant evidence is predictable; inspection lets a proposer investigate questions as they arise. Both are bounded and recorded.

    The experience concept distinguishes recorded history, disclosed observations, and the proposer's declared use. Access or a citation alone does not establish an improvement.

    Does it help?¶

    Compare runs with and without experience while holding the task, seed, proposer, and search settings fixed under comparable budgets. Inspect outcomes and experience usage as well as the best score: retrieving more history has a cost and need not produce better proposals. Keep final evaluation separate from the development evidence that guides revisions.

    The parser guide makes this comparison in a fresh notebook. Its proposer uses the latest failed checks to choose a minutes fix, then an hours fix. With feedback it reaches 100%; without feedback it keeps the seed at 33%, using the same three evaluations. This demonstrates the handwritten rule's use of observations, not model performance or accuracy on unseen inputs.

    Supported scope¶

    The mechanisms below are Shipped. Access is limited to authorized prior records within the same task and run. Cross-run knowledge reuse and semantic retrieval are Design—not shipped. Experience changes what a proposer may observe, never its evaluator, budget, permissions, or promotion authority.

    No memory¶

    With no context= or experience= declaration, a proposer receives no prior records. NoMemory states that policy explicitly when a named declaration is useful.

    Pushed context¶

    A plain callback reads this feedback through keyword-only context: def propose(parent, *, context): .... This opt-in supplies the authorized context object; the experiment still decides which observations it may contain. See callback migration for older signatures.

    A ContextPolicy selects a bounded bundle before each proposal. RecentAncestors favors the newest records in the current parent's lineage; AncestorsOnly retains the oldest records. BestSibling exposes a bounded sibling view. The selected structured records, rendered text, reason, logical time, and usage are committed before the proposer runs.

    import meta_evolve as meta

experiment = meta.Experiment(
    task=task,
    seed=seed,
    proposer=proposer,
    search=meta.Greedy(max_trials=3),
    context=meta.RecentAncestors(max_records=20, max_chars=4000),
)
result = meta.run(experiment)

    Read context.evidence.latest("your-evidence-kind") inside the proposer. It returns an immutable item with .data and exact .ref provenance, or None when the declared policy selected no match. Latest means last in selected order, including ties within a step. It may refer to an older ancestor or sibling. The accessor recognizes evidence labels from both proposers and evaluators; reserve your feedback label for its intended producer.

    Calling it with context disabled raises meta_evolve.errors.ContextDisabled, a CapabilityError, at the call site. Use context.evidence.enabled to make feedback optional in deliberate off comparisons. A declared empty policy is enabled even when no evidence matches; pull access alone does not enable it. context.evidence.truncated reflects omitted records or clipped rendering, without identifying the cause. Structured evidence remains readable with max_chars=0, while a small max_records can omit evidence entirely. Neither lookup nor status inspection performs a query or changes usage.

    Upgrading bounded feedback¶

    Existing context.bundle consumers keep working. Replace evidence filtering and max(logical_step) with context.evidence.latest(kind) when selected order is the intended rule; multiple same-step matches now resolve to the last item. Use .data instead of .value.data. Explicitly choose RecentAncestors for recency; AncestorsOnly@1 does not silently change retention. Manual context construction for tests or custom runners supplies context_policy to enable lookup. Workspace context replacement retains this declaration.

    This source change adds automatic proposer manifest dependencies for evidence lookup, disabled-context errors, and actual context construction. The shared context-policy source module also changes the hashes for AncestorsOnly and BestSibling, although their selection semantics remain the same. Historical stores remain readable; incompatible resumes refuse before new work. Continue old runs in their matching environment, or explicitly version changed author components and start a new run. Do not rewrite manifests or stored selections. The verification record records the old-store capture and exact digest changes. This follow-up does not change the selected #313/#319 release scope.

    Audited pull¶

    PullAccess grants bounded operations, result counts, records, and characters. The proposer uses an ExperienceReader only inside that grant. Each request, result, denial, and usage charge is retained; hidden or future records fail closed through typed access errors.

    For a SourceTree task, the same reader can inspect an exact prior artifact occurrence without receiving a whole repository implicitly:

    artifacts = context.experience.search(record_kinds=("artifact",), limit=1)
artifact_ref = artifacts.references[0]

listing = context.experience.list_source_paths(artifact_ref, limit=20)
read = context.experience.read_source(
    artifact_ref,
    paths=("solver.py",),
)
return meta.ProposalResult(
    candidate=revise(parent, read.files[0].source),
    derived_from=(read.artifact_ref,),
)

    Listings are lexicographic; reads preserve requested order. Both retain only a prefix of complete entries that fits the grant and charge the exact rendered characters. A missing path atomically denies the read. Canonical diff_source(older_ref, newer_ref) is also shipped: it verifies both prior occurrences, returns a bounded path-ordered unified diff, and charges two results. A source patch callback may instead request a bounded disposable Git presentation:

    from meta_evolve.adapters import GitHistoryView

proposer = meta.PatchProposer(
    edit,
    history=GitHistoryView(
        max_ancestors=4,
        max_archive_members=2,
        max_chars=128_000,
    ),
)

    The edit callback runs ordinary git log, git show, and git diff commands with cwd=context.workspace.root and env=context.workspace.environment. The selected parent remains HEAD; the manifest is available as context.workspace.history. Git metadata is external and disposable, and direct workspace mutation is rejected before the returned exact-file patch is applied. Whole-tree reader operations, semantic retrieval, and cross-run access are not shipped.

    Source-inspection contract¶

    Each target is an exact ExperienceRef(kind="artifact") occurrence for a SourceTree / utf8-tree-v1 value, in the same task/run and strictly before the effective observation boundary. The storage edge revalidates the digest before decoding. Equal bytes do not collapse distinct occurrences.

    ExperienceRequest.paths is an ordered tuple of strings; its empty default is omitted canonically from schema-v3 records. Wrong Python shapes fail before auditing. Empty reads, duplicate/non-normalized paths, wrong reference kinds, invalid logical time, and missing, hidden, future, retracted or cross-run targets enter the normal audit lifecycle and share an opaque denial. One missing path denies the whole read. Durable corruption and infrastructure failures stay typed.

    Authorization and existence checks precede capacity resolution. Listing/reading reserve one result; diff reserves two, after verifying older then newer operands. Operation/result exhaustion is recorded cumulatively. Record/character bounds retain the largest deterministic prefix of complete entries, charging one record per entry and exactly len(rendered) characters, including separators. An oversized first entry gives a successful truncated zero-record result after its result charge; an empty canonical diff is not truncated.

    Listings render lexicographically sorted normalized paths as compact JSON-string lines. Reads preserve requested order as compact JSON Lines with exactly path and source, stable keys, Unicode preserved, and no trailing newline. Diff uses meta-evolve-unified-diff/v1: sorted changed paths, optional filtering that keeps that order, LF-normalized lines with final-terminator state, deterministic Myers diff with deletion-before-insertion ties, three context lines, and changes merged across at most six unchanged lines. JSON file operands, uniform hunk ranges, missing-final-newline markers and complete per-path hunks are platform-independent.

    Source results in meta_evolve.domain retain occurrence refs, verified digests, complete entries, rendering, truncation and cumulative ExperienceUsage. Replay returns committed outcomes without live reads; durable loading independently reconstructs them from stored artifacts. Only successful observations authorize derived_from; diff admits its two operands in order.

    Git-history contract¶

    source-history-manifest/v1 is Git-neutral. Selection is parent first, then breadth-first causal ancestors, then archive order, deduplicated by occurrence. The head is the first entry; refs have one run and declared kinds, and parents stay within the authorized manifest. Equal digests may occur more than once. Each entry retains its digest, logical step, proposal/evaluation refs and selection rationale. Source bytes, Git IDs, environment values and repository layout are excluded from the manifest.

    The adapter uses the outer pull grant for a complete selected-parent listing, metadata search, ancestor traversal and complete additional-tree reads. It commits one SourceHistoryMounted before the callback. That fact records the manifest without new usage, operation category or derivation authority. Replay reproduces the audited prefix; durable loading revalidates observations and the manifest.

    Git objects, refs, configuration, index, attributes, hooks and home live in an external disposable sidecar. Selected-parent HEAD, causal commits and ephemeral archive refs present the authorized history. Direct workspace mutation remains a PolicyViolation; the sidecar is disposed before capture. Version/bounds changes alter configured proposer identity. This adapter adds no persistent Git identity, root export, experiment field or independent agent runtime.

    Declared derivation¶

    A rich proposal may declare which authorized observations influenced it. Those references are validated against the experience it actually received. Empty derivation remains compatible with ordinary callables.

    Causal provenance¶

    Everyday users can rely on Run.lineage(), Run.trials(), and RunExperienceUsage. Strict ledger ordering, logical-time validation, and replay are isolated in the advanced provenance reference. RunExperienceUsage.by_operation provides canonically ordered non-zero operation totals through meta_evolve.views.ExperienceOperationUsage; they sum exactly to the aggregate pull usage, in this order: search, open, ancestors, siblings, compare, list_source_paths, read_source, diff_source. History mounting reuses audited operations; it adds no category or duplicate charge.

    See authority and promotion for the roles that remain outside candidate control and their relationship to execution isolation.
