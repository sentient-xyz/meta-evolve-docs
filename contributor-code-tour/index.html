    Trace one run through the kernel¶

    After checkout setup, run the canonical example once and keep its two output lines in view. For a first introduction to the public API, start with the duration parser.

    uv run python examples/learn/number_search/main.py

    12
[0, 1, 2, 7, 12]

    The short script enters one coordinator. The actual order is interleaved:

    declaration
  → encode, evaluate, and atomically commit the seed
  → search decision and commit
  → proposal, candidate encoding, and commit
  → independent evaluation and commit
  → repeat until the committed stop decision
  → reopen the committed stream as a read-only Run

    No stage branches on “number.” The codec handles representation, the proposer handles mutation, the evaluator handles measurement, and search handles the next decision.

    Build and serve documentation¶

    From a checkout, build the complete site and serve it locally:

    uv sync --locked --group docs
uv run --group docs mkdocs build --strict
uv run python -m http.server --directory site

    Open http://127.0.0.1:8000. A saved documentation build includes its matching package ZIP. Repository collaborators can also download the meta-evolve-docs-<commit> artifact from a successful Docs workflow run on main. The artifact is private and retained for 14 days.

    Find the responsible component¶

    Use this map to enter the trace at the behavior you want to change. The linked checks exercise specific contracts; the architecture owns the invariants and the programming model owns the API.

    Responsibility Source entry Existing checks
    Declare and execute Experiment, Session Equivalent declarations and budget narrowing
    Preserve identity and history Domain identities, projection Task/run identity, distinct content occurrences
    Propose with authorized inputs Execution, proposal facts Proposer context and adapters
    Measure and account for work Evaluation, usage Evaluation facts before commitment
    Choose what to try next Greedy Shared search contract and limits
    Interpret a candidate policy Policy data, trusted interpreter Parent selection and hard budget, incomplete inner evidence
    Add a domain or integration Domain records, ports, adapters Published conformance suites, codec implementations
    Commit and reconstruct Coordinator, result views Atomic writes and conflicts
    Project authorized Git history Source observations, Git projection Mount, disposal, access, and tamper checks

    For the integrated author API, follow these focused boundaries:

    • Plain callback invocation and historical invocation checks separate explicit context from ordinary Python defaults.
    • Preset allowance resolution and default-limit tests bind the effective budget once, before recording the policy.
    • Component resources and accounting tests separate reported costs from engine-owned counts. The existing encoding and evaluation boundaries lower these reports into durable Usage.
    • Run summaries check reporting independently of successful winner selection.

    1. Declaration¶

    examples/learn/number_search/main.py declares the task, seed, proposer, search preset, budget, and random seed. The root meta.run export reaches application/runtime.py.

    runtime.run normalizes either declaration form and drives a Session. session_preparation.py chooses codecs, computes the effective budget, adapts callables, checks capabilities, prepares search, and derives run and task identities. Durable-local validation finishes before the coordinator can write an event.

    2. Encoding¶

    Preparation encodes the seed through CodecIndex.encode. A successor stays a Python value while the proposer works. encode_candidate in executors.py converts the returned value to a payload before proposal facts are built.

    A codec's TypeError or ValueError means invalid candidate output and becomes a typed failure. Another exception is a codec defect and propagates. Codecs do not choose artifact IDs, parents, scores, or promotion.

    3. Proposal¶

    execution.py loads only the committed parent artifacts named by the trial. It builds a ProposerContext from recorded randomness, logical step, objectives, bounded context, and audited experience, then calls the replaceable proposer runner.

    proposal_building.py checks usage and derivation authority, then builds the proposal, artifact occurrence, stable IDs, parent links, and provenance. proposal_completion.py commits those facts and drives any dependent evaluation. The proposer supplies content and evidence; it does not mint durable identity.

    4. Evaluation¶

    evaluation_execution.py calls the configured evaluator adapter, which decodes the committed artifact. build_evaluation then adds one evaluation charge, enforces effective budgets, creates stable evidence and evaluation IDs, and builds either measurements or a typed failure. The caller commits those facts.

    The evaluator is outside candidate authority. A candidate can fail a task and receive a real low score. A broken evaluator, exhausted resource, or infrastructure fault carries no metric and cannot be ranked as poor candidate performance.

    5. Search¶

    Session._step drives this local run. A prepared policy reads committed SearchState and returns a decision. The coordinator records it before executing a trial; a stop decision ends the loop. Recovery continues the committed frontier.

    Greedy's parent choice and retention rules live in policies/greedy.py, not in the coordinator. This is why BestOfN, Population, and a conforming custom policy use the same execution path.

    6. Commitment¶

    coordinator.py funnels every durable fact through commit_batch. It first folds the proposed events on a local projection and checks the same batch grammar recovery uses. Storage.commit then writes events and artifact occurrences together. Only a successful store commit advances the in-memory projection.

    batch_envelopes.py builds the same event identities and causation chain for provisional folds and the final commit. Context selections and experience audit facts also use commit_batch, each as a separate one-event batch.

    The seed follows the same rule through bootstrap.py: its declaration, occurrence, trial outcome, evidence, and evaluation form one genesis batch. A partial genesis is never a run.

    7. Projection¶

    projections.py rebuilds RunProjection by folding the ordered event stream. Replay consumes records; it never reruns the proposer, evaluator, context selector, or search policy.

    results.py projects read-only best, trials, lineage, summary, and comparison views. The printed lineage follows committed artifact parent IDs. It omits rejected 16 because that occurrence is not an ancestor of the winning 12.

    When the procedure becomes the candidate¶

    The two similarly named directories have different roles. policies/ contains search implementations such as Greedy. policy/ contains a PolicyArtifact and its trusted CandidatePolicy interpreter. The artifact declares parent selection and a voluntary trial limit; it cannot raise the enclosing budget.

    In policy evolution, the outer proposer changes that data. The outer evaluator runs bounded inner experiments using the interpreter and captures their outcomes. Both levels use the same runtime and have their own identities and work counts. The candidate-policy checks show how parent selection changes lineage while the hard budget stays fixed.

    Other methods choose what inner evidence to retain and which usage to forward. Compare policy evolution and AutoResearch before assuming that a saved outer run contains every inner history or total cost. The meta-evolution concept explains what further reuse and evidence would be needed to study recursive improvement.

    When the proposer uses Git¶

    GitHistoryView asks the experience interface for authorized source observations. application/source_history.py builds their manifest; adapters/git_projection.py turns it into disposable Git metadata outside the candidate workspace. The proposer can inspect that view with ordinary Git commands during its session.

    Artifact occurrences, evaluation references, and causal records remain framework data. Git commits represent only the permitted projection and are removed when the mount is disposed. The Git history checks exercise log/show/diff, cleanup, access declarations, and tamper rejection. The experience guide owns the read grants.

    Check source changes¶

    From the repository root after checkout setup, run the same source checks as CI:

    uv run --locked ruff check src
uv run --locked mypy

    Ruff checks shipped Python sources for unused imports (F401) and undefined names (F821). Declare intentional re-exports explicitly with __all__ or from module import name as name. Run the relevant behavior tests from the component map above for the code you change.

    Mypy checks application host interfaces in the source roots listed in pyproject.toml. Imported modules retain their types; diagnostics are limited to those roots. tests/typing/host_contracts.py checks the concrete coordinator against each host protocol. Add new host modules to the configured roots and include their implementation assignments in that file. Runtime conformance, transaction, and authority tests remain part of uv run pytest.

    Exercises on the invariants¶

    Authority¶

    In proposal_building.py, list the fields copied from proposer output and the fields minted by core. Explain why moving artifact ID creation into the proposer would let a candidate overwrite history.

    Identity¶

    Change only random_seed in a temporary number-search run. Predict which run identity changes and which task identity stays fixed. Then find both inputs in session_preparation.py and run_support.py.

    Lineage¶

    Sketch the parent IDs for attempts 1, 6, 11, 16, and 12. Explain why two artifact occurrences with equal payload bytes still need distinct IDs.

    Budgets¶

    Account for the example's six evaluations and five successor trials. Identify where the seed is charged, where proposal usage is checked, and where evaluator usage is checked. No component may widen the effective budget.

    Typed failures¶

    Classify these outcomes: a candidate violates the task, a codec rejects the candidate type, the grader crashes, and a proposer exceeds its resource grant. Only the first can be an ordinary low score.

    Replay¶

    Read commit_batch beside replay_run_projection. Name the shared fold and grammar checks that keep “committed” equivalent to “recoverable.” Explain why replay must not ask the proposer for the same candidate again.

    Comparison validity¶

    Use the CLI walkthrough to compare Greedy and BestOfN. Then list the declarations that must match before the winner is meaningful. A displayed winner is not evidence when task, evaluator, initial artifact, budget, proposer, or hidden component configuration changed.

    Continue by purpose: compose a method, add an artifact domain, or follow a linked invariant test into its implementation. The harness guide teaches the current example; historical evidence retains the earlier design rationale.
