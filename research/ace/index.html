    ACE: improve an itemized playbook¶

    Status: Shipped. Evidence: deterministic mechanism demonstration; no live model gains or cross-task transfer claim.

    What it does. ACE improves an agent's reusable context as an itemized playbook, preserving useful rules while correcting or adding specific entries.

    How it works. A Generator attempts tasks, a Reflector extracts lessons, and a Curator applies incremental playbook edits. Later attempts use the updated playbook. Here, deterministic lesson extraction and curation change company-specific tagging rules; independent checks select a playbook, test consolidation, and measure held-out behavior. This demonstrates itemized updates rather than the complete learned ACE system.

    The concrete problem¶

    An agent tags a company's financial disclosures. The note says “cash paid for interest,” but the company requires nwi:InterestPaidNetOfCapitalized rather than the generic taxonomy element. The starting playbook contains the wrong interest convention and no lease convention. Improving the context should change the answer while the company's grading rules remain fixed.

    For a smaller notebook introduction, start with Improve a support agent's playbook: six support tickets, three named rules, and one revision per recorded mistake.

    Component worksheet¶

    Question This implementation
    What changes? A Text JSON playbook with stable item identities, content, section, and status
    What generates the change? ace_curation.revise(lessons) corrects an entry, then adds a missing convention, using published development lessons
    What judges it? playbook_suite(agent) independently grades private task answers; Greedy(max_trials=2) maximizes solved and stops at 1.0
    What is retained? Outer search records, selected playbook, failures, and usage; in-memory study results hold the other phases and their inner captures

    Split membership, the agent declaration, inner budgets, and the neutral-only consolidation rule remain fixed. Private answers do not enter the curator's development lessons. Saving the outer search does not persist or resume the whole study; study.usage accounts for all phases, while study.run is search only.

    What the paper does¶

    ACE, §3 separates a Generator's task trajectories, a Reflector's lessons, and a Curator's context updates. It edits individual identified bullets rather than rewriting the whole context. Incremental deltas and a grow-and-refine process maintain useful context while controlling redundancy. The paper supports repeated and online adaptation.

    Here the agent is a deterministic fixture. Python extracts authored lessons, curates entries, and performs one consolidation after search. This preserves an itemized-update demonstration, not the paper's learned reflection, semantic retrieval/deduplication, helpful/harmful counters, or online adaptation algorithm.

    Follow the two levels¶

    OUTER: seed playbook → curate/add → private score → select
                          ↑              │
                development lessons      │
                                         ↓
INNER: playbook + fixed agent + input → task answer
                                            ↓
                                     independent check

After selection: consolidation check → held-out evaluation

    Outer work allows three evaluations and two revisions. Each inner rollout allows two evaluations, one revision, and 120 seconds. At most fourteen fixture agent calls cover development, private search, matched consolidation, and held-out work.

    The revision mechanism¶

    The curator returns a proposer that changes one identified entry at a time. Its input is the published development lessons, so private answers cannot be added by a context policy behind the reader's back. The actual edit logic is:

    ace_curation.py · curate
    def curate(playbook: Playbook, lessons: Sequence[Lesson]) -> Playbook | None:
    """Amend items a lesson can rescue; retire the ones nothing supports.

    Returns ``None`` when every active item is already aligned, which is the
    signal to generate instead. Retired items are left in place rather than
    dropped: pruning them is consolidation's job, and consolidation acceptance
    belongs to the evaluator.
    """

    pending = list(uncovered(playbook, lessons))
    revised: list[PlaybookItem] = []
    changed = False
    for item in playbook.items:
        if item.status != "active" or aligned_with(item, lessons) is not None:
            revised.append(item)
            continue
        rescue = next(
            (lesson for lesson in pending if lesson.section == item.section), None
        )
        if rescue is not None:
            pending.remove(rescue)
            revised.append(item.amended(rescue.content))
        else:
            # Nothing published supports this entry, so stop telling the agent
            # it. Retiring keeps the record readable; deleting would not.
            revised.append(item.retired())
        changed = True
    return Playbook(tuple(revised)) if changed else None

    If curation finds no change, generate adds the first uncovered lesson:

    ace_curation.py · generate
    def generate(playbook: Playbook, lessons: Sequence[Lesson]) -> Playbook | None:
    """Append an item for the first lesson the playbook does not state yet."""

    pending = uncovered(playbook, lessons)
    if not pending:
        return None
    lesson = pending[0]
    item = PlaybookItem(
        identity=lesson.identity, section=lesson.section, content=lesson.content
    )
    return Playbook(playbook.items + (item,))

    The independent playbook_suite executes each candidate with a fixed agent and checks its answers against evaluator-owned company conventions. study_playbook collects development lessons before search, tests neutral consolidation after selection, and then checks the held-out split. The complete download includes each stage.

    Setup and run¶

    Use Python 3.12+ on macOS or Linux. Download the source package and complete context example into a new directory. The ZIP retains the example's directory structure and all sibling modules.

    python3 -m venv .venv
. .venv/bin/activate
python -m pip install ./meta-evolve.zip
python -m zipfile -e context-example.zip .
python examples/research/context_evolution/main.py --sibling ace
# Output excerpt (other study phases are also printed):
# trial scores: ['0.0', '0.5', '1.0']
# solved: 1.0

    From a checkout, use uv sync --locked and uv run python examples/research/context_evolution/main.py --sibling ace. No model credentials or provider requests are involved in this fixture.

    Verified fixture excerpt
    trial scores: ['0.0', '0.5', '1.0']
solved: 1.0

    The first edit corrects interest tagging; the second adds the lease rule. The retired scale entry remains in history until consolidation removes it. The fixture's final held-out solved fraction is 1.0, demonstrating the split boundary on these authored cases. An incomplete split is unrankable, never an average of only its successful rollouts.

    Change and predict¶

    Disable the lease lesson in a scratch copy of the development fixture. Predict which private task cannot improve and inspect the proposed entries. Restoring that lesson should restore the two-step progression. Changing the agent requires an explicit InnerAgent model, revision, and non-secret configuration.

    Evidence and limitations¶

    Context tests verify the transcript; companion tests cover split isolation, transition failures, identity, and replay. The notebook is an existing supplement. #194 owns the implemented example; #192 owns later research scope. Nothing here reopens its completed migration.

    Durable replay covers outer search. Development, consolidation, and held-out outcomes remain in-memory study results; saved search does not make them resumable.
