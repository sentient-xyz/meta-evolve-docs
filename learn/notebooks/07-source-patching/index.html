    Evolve immutable source with an external grader¶

    This historical supplement retains its distinct deterministic examples and recorded evidence. For the current parser-based sequence, use Start here; no earlier lesson is required to read this page.

    So far, artifacts were small Python values. This chapter follows the same declarative loop when the artifact is a directory of source files and the evaluator is a real subprocess outside candidate authority.

    Open the canonical executed notebook only if you want to execute the cells; this page explains the full lifecycle.

    What it teaches¶

    The complete repair is:

    load immutable UTF-8 source
  → propose one exact file replacement in a private workspace
  → capture a new immutable SourceTree
  → materialize it in a fresh evaluation workspace
  → run an external grader under a declared process protocol
  → commit score, evidence, usage, and parent lineage

    The original checkout is never modified. A candidate proposal cannot include grader edits because the grader is not part of the candidate artifact. Runtime host isolation is a separate concern explained below.

    The broken program¶

    The candidate tree contains one file, clamp.py. Its documented job is to keep value between low and high. The seed implementation is wrong; the desired replacement is:

    def clamp(value, low, high):
    return max(low, min(value, high))

    The evaluator-owned tests include values below, inside, and above the interval. The seed scores 0; the repaired successor scores 1.

    Step 1: load an immutable SourceTree¶

    source = meta.load_source_tree(staged)
print("loaded immutable source:", tuple(source) == ("clamp.py",))
    Output
    loaded immutable source: True

    The loader recursively captures exact relative paths and UTF-8 text. It rejects:

    • symlinks;
    • binary or non-UTF-8 content;
    • non-regular files;
    • unsafe or ambiguous paths.

    There are deliberately no ignore rules. A generated __pycache__ changes the directory being declared and is rejected rather than silently omitted. Stage only intended files into a clean directory when tools may have left debris.

    SourceTree is immutable. A successor is new content with parent lineage, not an in-place edit of source.

    Step 2: describe one exact patch¶

    def repair(tree, context):
    return meta.TextPatch(
        path="clamp.py",
        expected=tree["clamp.py"],
        replacement=FIXED,
    )

    expected is optimistic concurrency for file content. The patch applies only if the private workspace still contains the exact parent text the proposer saw. This prevents a stale patch from overwriting an unexpected revision.

    PatchProposer owns the workspace lifecycle:

    materialize parent → invoke patch callback → validate path/expected/replacement
→ apply exact edit → capture SourceTree → dispose workspace

    Invalid path, conflict, unchanged replacement, malformed patch, and cleanup failure remain typed proposal outcomes. They are not low task scores.

    Step 3: keep the grader external¶

    The evaluator declaration is:

    evaluator = meta.CommandEvaluator(
    command=meta.ProcessSpec(
        argv=(python, "run_grader.py", "grader.py"),
        environment={"PYTHONDONTWRITEBYTECODE": "1"},
    ),
    environment=meta.EvaluationEnvironment(
        name="python-clamp-tests",
        version="1",
    ),
)

    For each candidate, CommandEvaluator creates a fresh workspace, materializes only the candidate source, runs the fixed command, captures bounded output, and disposes the workspace.

    grader.py and run_grader.py live outside the SourceTree. The candidate cannot propose changes to them because they are not in its artifact or proposal workspace.

    The exit protocol¶

    The fixed runner translates process behavior into domain outcomes:

    Exit Meaning Outcome Rankable?
    0 Candidate passes score=1 Yes
    1 Candidate fails tests or cannot load score=0 Yes
    Other Grader/protocol broke EvaluatorFailure No
    Timeout Process exceeded wall limit TimeoutFailure No

    Candidate syntax error is rankable failure because the task is to supply working source. Missing grader is not candidate performance; scoring it 0 would reward infrastructure reliability as though it measured code quality.

    fault = broken_evaluator(source)
process = next(item for item in fault.evidence if item.kind == "process-result")
print("grader fault:", type(fault.failure).__name__)
print("grader fault rankable:", bool(fault.metrics))
print("grader fault process exit:", process.data["exit_code"])
print("grader fault evidence kinds:", [item.kind for item in fault.evidence])
    Output
    grader fault: EvaluatorFailure
grader fault rankable: False
grader fault process exit: 2
grader fault evidence kinds: ['evaluation-environment', 'process-result']

    Step 4: budget seed and successor¶

    budget = meta.Budget(evaluations=2, trials=1)
task = meta.Task(
    evaluator=evaluator,
    artifact=meta.SourceTree,
    budget=budget,
)

    Two evaluations cover the broken seed and one proposed successor. One trial authorizes the patch. The task owns this coordinator ceiling.

    Step 5: run the ordinary loop¶

    experiment = meta.Experiment(
    task=task,
    seed=source,
    proposer=meta.PatchProposer(repair),
    search=meta.Greedy(max_trials=1),
)
result = meta.run(experiment, storage=storage, mode="local")

    No coordinator branch knows this is Python repair. The artifact codec handles SourceTree; the proposer handles patches; the evaluator handles process execution; Greedy sees only rankable outcomes.

    Step 6: read immutable evidence¶

    The saved run prints the evaluator-owned evidence and causal result:

    print("source digests:", digests)
print("scores:", scores)
print("process exits:", exits)
print("failures:", failures)
print("evidence kinds:", kinds)
print("repaired best:", best.value["clamp.py"] == FIXED)
print("parent unchanged:", source["clamp.py"] != FIXED)
print("lineage length:", len(lineage))
    Output
    source digests: ['659bfe4a9f389018a5059f9045d6db37592c017591629d6baf5a7ab52792ca53', '08abe248cf356c0ee0322aa9329598221640460d6cf0202228097d7f4c4c21c0']
scores: [0.0, 1.0]
process exits: [1, 0]
failures: [None, None]
evidence kinds: [['evaluation-environment', 'process-result'], ['evaluation-environment', 'process-result']]
repaired best: True
parent unchanged: True
lineage length: 2

    Each lineage entry includes a content digest. The repaired tree has a different digest and names the seed artifact as its parent. Reopening durable storage can read the same best artifact and lineage without touching the checkout.

    Process wall time is occurrence evidence, not deterministic identity. Content, declarations, scores, and semantic outcome are the stable parts of this local example.

    Durable history is not cold resume¶

    The run uses durable storage but mode="local". Its live patch callback, command evaluator, and workspace providers have no portable reconstruction manifest. Therefore:

    with meta.Storage.durable(history) as reopened:
    durable = meta.Run(result.id, reopened)
    print("reopened best:", durable.best() == best)
    print("reopened lineage:", durable.lineage() == lineage)
    try:
        meta.resume(result.id, storage=reopened, registry=meta.Registry())
    except meta.CapabilityError as error:
        if "not resumable" not in str(error):
            raise
        print("cold resume: CapabilityError (local run is not resumable)")
    else:
        raise RuntimeError("local workspace run unexpectedly resumed")
    Output
    reopened best: True
reopened lineage: True
cold resume: CapabilityError (local run is not resumable)

    Failing closed is important. Substituting a different grader or patcher after a restart would create one run ID with two behaviors.

    The subprocess boundary is not hostile isolation¶

    DevelopmentSubprocessSandbox controls working directory, environment, timeout, process-group termination, and retained stdout/stderr. It does not isolate network, CPU, memory, syscalls, or arbitrary host filesystem access.

    Use a hardened container or other isolation provider for untrusted code. Do not describe this development boundary as a security sandbox.

    What to notice¶

    • Candidate authority is exactly the files inside the immutable tree.
    • Exact patches prevent stale overwrite and preserve the parent.
    • Proposal and evaluation use separate fresh workspaces.
    • The external grader remains outside candidate lineage.
    • Candidate-caused failure is rankable; evaluator failure is not.
    • Durable inspection does not imply resumable execution.

    Interpretation questions¶

    1. Why include expected text in a patch?
    2. Why is a candidate syntax error score 0 while a missing grader has no metric?
    3. Does SourceTree prevent candidate code from accessing the host at runtime?
    4. Why can the run reopen but not resume?
    Answers 1. It ensures the patch applies to the exact parent revision the proposer saw. 2. Syntax validity is task performance; missing evaluator infrastructure means the task was never measured. 3. No. It bounds the versioned artifact and workspace capture, not hostile-code runtime authority. 4. Stored artifacts/events are portable, but the local live callbacks and providers are not reconstructable from a registry manifest.

    Change and predict¶

    Change the replacement to invalid Python.

    Predict: the patch itself is structurally valid and commits a new source tree; the external runner exits 1; evaluation returns rankable score=0; Greedy keeps the original seed as best; the failed candidate and its process evidence remain in run.trials() but not in the winning lineage.

    You now have the complete basic path: declare a task, choose search, compare it fairly, reuse experience causally, recover durable work, and evolve real source under an external evaluator.
