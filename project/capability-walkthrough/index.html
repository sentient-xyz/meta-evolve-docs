    Capability-lesson newcomer walkthrough¶

    This is the revised task handoff from #281 to #275. Use #277's exploratory findings and reusable regression checklist to record each scenario's cells or commands, expected and actual result, environment, tested commit, assistance needed, outcome, and linked defects.

    This page is a facilitator's handoff. Give participants the prompts below one at a time, without the expected results in the observer checklist. The walkthrough checks whether someone can find, explain, and adapt an experiment, as well as execute its cells.

    Run a session¶

    1. Start with a reader who can use Python functions and notebooks but has not used Meta-Evolve. Record their relevant experience and any prior exposure to these docs. Use an empty notebook and working folder, without a checkout.
    2. Record the documentation source/build revision, package version, installation URL or archive hash, and imported package location, then open the homepage. Let the reader choose links; do not supply a direct guide link unless help is needed.
    3. Ask them to think aloud. Record the first point where they hesitate, their interpretation, and the page, heading, or cell involved. Ask neutral questions such as “What do you expect this to do?” Avoid explaining the API for them.
    4. If they ask for help, record their attempted approach before helping. Mark that task as assisted even if it succeeds afterward. Stop at a blocker when continuing would only repeat the same problem.
    5. Use a new notebook for the chosen task guide. Observe whether the reader finds and executes required setup, including any folded cells, without prompting. Record time to find the guide, first successful task result, and independent adaptation; separate installation delays from reading and coding time. Complete further guides in later sessions; preserve code and outputs for every attempted task.
    6. For their own evaluator, measure time to a completed bounded experiment and an inspected result. The seed may remain selected; a positive score delta is not required. Observe feedback problems before asking the diagnostic questions below, and distinguish an unprompted discovery from a prompted task.

    Participant prompts¶

    Give only the current prompt to the participant. The first four form the common entrance walkthrough; the last prompt checks transfer after a task guide.

    1. Find and run: “Starting on the homepage, find a first example you can run without a model account. Set it up in your notebook and run it.”
    2. Explain: “Point to what changes, what proposes a change, and what decides whether it is better. Explain what happened between the printed scores.”
    3. Predict and adapt: “Allow just one revision. Before running, predict the number of evaluations and which inputs will still fail. Run it and use the selected parser on a new input.”
    4. Find a task: “You want to keep the result and inspect it after restarting Python. Find the relevant instructions, then try them in a fresh notebook.”
    5. Transfer: “For a small problem of your own, implement a starting value, revision function, and measurement function. Use the documentation to run a bounded experiment and use its selected result. Explain which rules stay outside the revision.”

    For another guide, state the desired outcome in ordinary words before giving its title: for example, “Use failed test cases to guide the next revision.” Then use that page's change-and-predict exercise. Record the prediction before execution, the explanation afterward, and any help required.

    After the exercise, ask a question relevant to that guide without naming the answer's location: “Why didn't my new metric change the winner?”, “Why did search revise a weaker version?”, “Why isn't feedback reaching my proposer?”, “Why wasn't the last attempt selected?”, or “Do I need the original functions to reopen?” Record their route, answer, and any assistance. Returning readers should also find the relevant operation with shared setup closed.

    Tasks for an unfamiliar reader¶

    For the tool-choice page, add these unaided retrieval tasks:

    • Starting at the homepage, decide whether Meta-Evolve fits a small idea of your own. Identify the starting value, revision function, and independent grader; find a guide you could adapt. Explain one reason to choose a bundled optimizer.
    • Find whether closing Python preserves a default run, whether saving makes it resumable, and whether a spending ceiling prevents every overrun.
    • Find what evidence would support a live improvement claim. Separate the handwritten parser's measured scores from model performance.

    Record time to find each answer, navigation or search route, interpretation, and assistance. These tasks extend #275/#277; agent checks are not human results.
