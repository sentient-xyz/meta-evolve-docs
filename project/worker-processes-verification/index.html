    Worker-process stabilization verification¶

    Stabilization baseline verified September 21, 2026 for #353. The repair plan records scope; the execution contract owns usage.

    Source and scope¶

    The completed stabilization run checked local revision 9f72cae5f7c281b1bad28075dc77e723b45f4d27 on codex/353-worker-stabilization, based on PR head 170e4a26b8401b6d6560d9b18b459cac60595791. This receipt was added afterward; it changes no runtime or test source. At that checkpoint the original main working tree was preserved, and no branch had been pushed or merged. Subsequent authorized stack integration is tracked below.

    Commit Repair
    f7aa7db6 Reject malformed MACs and invalid UTF-8 body encoding as connection-scoped handshake refusals.
    4a7a1fd2 Retain completed results before writing, reconnect on socket-operation failures, close served sockets, and refuse crossing run identities with a pending result.
    e04ce617 Recheck and reserve identity at final admission, preserve ownership throughout a pending batch, and clean up only the failed connection's reservation.
    238bdead Replace a handshake test's fixed spin count with bounded socket-readiness waiting.
    9f72cae5 Align default inline execution, explicit process backends, admission ordering, and remaining M11 scope across documentation.

    These repairs add no durable schema, root API, coordinator special case, worker administration, or new retry policy. The existing M11.3 stack remains the base; this verification does not close the broader M11 acceptance gate.

    Regressions demonstrated before the fixes¶

    • A non-ASCII MAC raised TypeError through both the real host handshake and pending dispatcher admission. A separate escaped-surrogate body raised UnicodeEncodeError before authentication could return a refusal.
    • Write-side loss raised BrokenPipeError instead of retaining the completed result. The initial worker regressions produced 13 failures and 2 passes. The cross-run probe separately demonstrated an old result being forwarded to a newly admitted run; its refusal regression failed before the guard.
    • Three overlapping-admission cases accepted two peers instead of one: different incarnations of an external ID, and same/different incarnations competing for a minted slot. Every Hello preceded either final Manifests.

    The repaired tests use real framed socketpairs, explicit execution barriers, the production pending-admission loop, and an actual dispatcher lease. They prove a malformed peer cannot prevent a valid worker from completing bootstrap evaluation, a completed call is not repeated across failed resends, and a late contender cannot release the first owner's lease or its accepted result. Cleanup cases cover failed admission writes, same-incarnation reconnects, batch exceptions, and endpoint handoff failures. CLI preflight is exercised too.

    Independent code review checked admission ownership and worker pending-state handling. Focused suites passed before the integrated run, including the existing real-process reattachment, interruption, and cleanup tests. These overlapping focused counts are not added to the complete-suite count below.

    Stack integration¶

    After the stabilization baseline passed, the user authorized pushing and merging the #353 stack, reconciling related issue tracking, and updating documentation. The final runtime revision is 0288969125c1ff58041615488629130ac9c2d3aa, which integrates the repaired #341 base and main 4af50b40. This receipt update changes documentation only; the baseline counts above remain a separate run.

    Review of #341 found an additional liveness case: after one completion blocks, the next completion must consume buffered heartbeats before protecting its own lease. The regression produced Accepted followed by Stale(EXPIRED) before the repair, and two accepted results afterward. EOF and failed-neighbor cases preserve final broker authority and connection-scoped failure handling.
