    Trusted-worker administration verification¶

    Initially verified September 23, 2026 for #203, the M11.4 slice. The plan records scope and the decisions AD1–AD7 and PD1–PD8; the design record owns the rules; the command-line guide owns usage.

    Mutations that did not redden a law¶

    Every law was planted with its named mutation and watched going red, except these. They are retained as the commits reported them. Every law the review round and the /pr-review round added went red under its named mutation (the one law that pins existing behaviour is noted below), so none is listed here.

    • Removing the Hello trust read alone (b1f6d3cf) leaves the process laws green: the second read, just before the reservation, refuses the same worker. The ordering is pinned in tests/test_worker_trust_admission.py instead.
    • Dropping the sweep's generation arm on the submission path (b1f6d3cf) leaves the process law green: answering a revoked holder releases its lease, and that release is the broker write that frees the row. The sweep laws pin the arm.
    • Keeping the verifier when the sweep frees a lease (ec10930a) leaves every law green: the cause write already refuses a later diagnosis, and every other path meets the generation check first. The verifier is cleared because the record requires it and because it is one statement shared with release and rollover.
    • workers list opening the store durable (b54a0e65) leaves the held-store law green, because SQLite tolerates a second writer; the read-only claim rests on the byte-identity law.
    • Skipping the shared freeze of a declared capability (e75a1891) stays green: the value is also frozen by the SQLite encoding and compared by canonical bytes, so any one of the three is masked by the other two. The command-line array law goes red instead under "the command line takes arrays and objects as literal text".
    • Three identity mutations (0dfebf06) go red through the replay fold's own refusal rather than the law's assertion: a second guard in the domain.
    • The revoked-door law's cost assertions (24bb74e1) — rows ready at attempt 0, epoch unchanged — cannot redden under a door mutation, because the handshake holds no broker and acquire refuses a revoked worker on its own. They record the refusal's cost rather than guard it.

    Failed attempts retained¶

    • The first real-process revocation law found a defect the wire laws had missed (b1f6d3cf). A revoked holder's result is classified by submission_status, which is a read and moves nothing, and the dispatcher drops the binding before settling, so the row stayed LEASED with nothing bound to it and the undecidable-frontier refusal aborted the drive. "Freed at the next broker write" had no next write on that path. Answering a revoked holder now releases its lease first. The wire law that had asserted rows() == before for that path was pinning the stranding, and now asserts the release.
    • The durability guide, the plan page, a law's docstring and a commit message once said an unreadable trust row stops every run in the store. The sweep is scoped to its run, so it stops only the runs its worker holds a lease in; the documents were corrected in 24bb74e1 and the law now pins both halves.
    • The byte-gate script used for the first pull request drives inline durable-local runs, distributed runs at widths 1–3 under the default inline execution, and three failure paths. It spawns no worker process, so on its own it does not cover --workers N. For this receipt a second script drove the same fixture through WorkerProcesses(1) and WorkerProcesses(2) on both trees; see the gate table.
    • During the live check below, a first ps | grep -c for leftover workers counted 1. The one match was the invoking shell's own command line, which contained the search text; listing the matching lines on the rerun showed no worker or dispatcher process.

    Negative claims¶

    • No paid run was made and none was needed: the live check used the test fixture, and experiment 17 ran with StubProvider.
    • Nothing entered the closed wire error map _ERRORS: src/meta_evolve/distributed/messages.py is unchanged on the branch. WorkerRevoked is a cause recorded on a row, never an exception on the wire.
    • A host is handed a lookup that reads only through a reader: the store hands out a reader, and tests/test_trust_lookup_handoff.py shows a drive's lookup never asks for write authority. No claim is made that authority is unreachable through the object graph.
    • The frozen schema-4 stores under tests/fixtures/api_v01/ are untouched: the branch changes nothing under tests/fixtures/, and they open read-only byte-identical.
    • No root export, no event byte and no DURABLE_TYPES entry was added.
    • This receipt claims no multi-host or TLS validation, no concurrent renewal-versus-expiry or over-capacity race test (#204), no canonical trusted-workers example (#205), and no completion of M11.5–M11.6. The design record stays Design—not shipped until the milestone gate closes.

    September 26 integration follow-up¶

    The follow-up to c0781f12 addresses the final repository review:

    • Administration commands report the row their transaction committed. They no longer classify an operation using a separate earlier read. Two deterministic interleavings over separate SQLite connections cover concurrent revoke during add and concurrent re-enrolment during revoke (tests/test_cli_worker_administration_races.py). The earlier CLI transcripts above remain historical; the command-line guide shows the current output.
    • A listening host obtains the store's live enrolment reader before creating its key, binding its port, or rolling the epoch. Missing registry support fails at open; spawned backends leave the factory unused. The handoff tests retain the reader-only boundary and prove that subsequent registry changes are visible.
    • Repeated source explanations are condensed. Documentation checks retain published anchors, contract references, availability, and evidence links without requiring exact prose or section adjacency.

    The focused regression set passed all 108 tests, including real worker processes. Ruff, mypy's 30 configured files, compilation, and whitespace checks also passed. Full integration verification is recorded in the pull request.

    September 26 boundary follow-up¶

    Review of the integrated second slice found three remaining input boundaries:

    • Nonces of the right character count could grow through JSON escaping and exceed a tight Terms frame bound. Admission now requires the hexadecimal format workers mint. tests/test_handshake_nonce.py covers malformed values, unchanged queued work, and a healthy worker admitted under the same bound.
    • Unexpected exceptions retained their connection buffers through an unbounded refusal history. The listener now retains its latest 16 refusals. tests/test_handshake_retention.py verifies eviction, collection of the old handshakes, and preservation of recent exception tracebacks.
    • Excessive capability JSON nesting escaped the command-line usage-error path. tests/test_cli_worker_capabilities.py covers both parsing and recursive value validation, with an exit-2 refusal before any store opens.

    All 138 focused regression tests passed, including real worker processes. Restoring the three defects made all four targeted regression checks fail; the fixes were then restored. Ruff and mypy passed. The follow-up pull request retains the full integration check results.
