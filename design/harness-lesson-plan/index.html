    Harness lesson: plan for #351¶

    Status: Design—not shipped. This is the planning record; the live verification identifies the implemented lesson and its remaining capture gate.

    September 21 revision: a standalone live lesson¶

    The user approved a seven-cell live adaptation, following Feedback Descent and EvoSkill, and required the notebook and copied documentation to be independently usable. This extends the earlier fixture-only lesson scope below. M11 remains the runtime boundary; the live example uses shipped callable and harness interfaces.

    examples/research/meta_harness/main.py owns the visible declarations. Its SDK, grading, phase, and display modules remain example-local. A generated notebook and page share all seven cells; setup fetches a content-addressed, verified archive containing every support file. No checkout or companion upload is needed. The original study and its verification move together to the deterministic reference page and retain the harness-example.zip download.

    Both proposer and worker use actual Claude SDK sessions. Mutations affect only planner text or whether the repository contract enters worker context. Generated repairs run in confined Python children; expected answers stay in the parent. All rankable development occurrences get private checks, selection freezes, and matched held-out runs determine export eligibility. Full receipts reconcile usage. The initial live path is explicitly Experimental/live-only, without claiming full paper reproduction, live resumability, or guaranteed improvement.

    Acceptance covers deterministic SDK stubs over real execution, failure and authority boundaries, independently downloaded notebook and copied-page execution, strict rendering and visual inspection, then an authorized live capture. The notebook's first cell must supply all setup, and every code cell stays below 40 lines. The live lesson verification records the delivered reading paths and the remaining live capture.
