    SDK accounting and tools¶

    For a complete runnable notebook, start with Use your model SDK. This reference covers richer return values, exact billing conversion, and audited tool callbacks. SDK-specific snippets below are patterns to adapt to your own client.

    Understand the notebook's results¶

    The introductory notebook uses ask_model for both the rewrite and evaluation requests. It returns a ProposalResult carrying either text or a typed failure, plus Resources and EvidenceDraft observations. The evaluator forwards the same usage and evidence into its EvaluationResult. Its fixed expected answers and grading rule stay outside candidate authority.

    Observation Notebook behavior
    Completed, nonempty text The proposer returns a candidate; the evaluator grades returned labels.
    Wrong labels or label count A valid measurement: incorrect labels fail checks; a wrong count fails all checks.
    Empty or incomplete response with known usage InvalidOutput, no score, retained tokens and response evidence. A failed rewrite has no successor to evaluate.
    Request exception, missing/invalid token counts, or unusable response structure ExecutionAccountingUnknown escapes with the original error as its cause; execution stops without invented zero usage or an automatic retry.
    Tokens known, exact bill absent Tokens remain usable; spend_micros=None propagates as unknown spend. This alone does not make a response fail.

    Input plus output tokens enter shared usage; cached input is already included. The notebook retains elapsed request time, response ID, returned model/status, request text, output, and token counts. Evidence records describe one execution, not a guarantee that another request will reproduce it. The official SDK tests use simulated HTTP responses; their scores and token counts are not live results.

    max_trials=1 allows at most three requests: seed evaluation, rewrite, then revision evaluation. Each evaluation batches the six tickets into one request. The notebook disables automatic retries. Its output allowance is per request, not a cap on total tokens or money; its timeout is not a hard run deadline. trials(), inspect(), best(), and usage() read recorded history without requests. Rerunning meta.run() performs another experiment.

    Replace the SDK boundary¶

    Replace the client construction and ask_model on the introductory page. Keep the proposer and evaluator as ordinary callables; there is no first-party provider adapter or generic provider runtime to configure.

    The notebook records the SDK version, request settings, and client options in Task.environment, making them part of experiment identity. The API key stays in client construction, outside configuration and evidence. When adapting the example, record behavior-affecting settings without credentials and rerun the declaration after changing them. store=False controls provider response storage; it does not disable the local evidence retained by the wrapper.

    Preserve usage and failure reporting when changing clients. Use the three paid-call failure cases below rather than dropping accounting to return plain text. See the Responses API reference for the introductory client's request and response fields.

    Return a typed result¶

    Use ProposalResult when the wrapper has more to report. This and the my_sdk tool example below are user-supplied SDK pseudocode:

    def propose(parent):
    response = my_sdk.generate_structured(input=parent)
    return meta.ProposalResult(
        candidate=response.artifact,
        usage=meta.Resources(
            tokens=response.input_tokens + response.output_tokens,
            # Charged spend is shared usage; estimates stay evidence.
            spend_micros=response.charged_micros,
            wall_seconds=response.elapsed_seconds,
        ),
        metadata={"model": response.model},
        evidence=(
            meta.EvidenceDraft(
                kind="sdk-response",
                data={"estimated_cost": response.estimated_cost, "raw": response.raw},
            ),
        ),
    )

    Total tokens, charged monetary spend, and elapsed time enter Resources, then recorded Usage with engine-owned counts. Model identity, estimated cost, granular token categories, and raw provider telemetry belong in evidence or metadata: only a figure the provider actually billed may become spend_micros. When no bill is available, explicitly report spend_micros=None. Keep input and output tokens; cached input and reasoning output are generally subsets, so use the SDK's documented totals without counting those subsets twice. A valid response remains usable. Unknown spend propagates through sums and stops further work under a monetary ceiling, as described in Money.

    When a paid call fails, a wrapper has three cases, and the last is the one that is easy to miss:

    1. tokens and other required measures are known — return a typed failure carrying that usage, with unknown billed spend represented by None;
    2. the failure happened before any paid work — return a typed failure with zero usage;
    3. work may have started and required measures such as tokens are unavailable — raise ExecutionAccountingUnknown.

    The names come from two submodules:

    from meta_evolve.domain import InvalidOutput          # and the other failures
from meta_evolve.errors import ExecutionAccountingUnknown

    Known spend_micros is an integer, so convert before reporting — a float raises. Round up, so the framework never under-reports a charge, and keep the raw provider figure in evidence as provenance.

    Convert through Decimal, not by multiplying the float. Binary floats do not hold decimal amounts exactly, and the error goes the wrong way at exact micro boundaries: 0.000123 * 1_000_000 evaluates to 123.00000000000001, so a math.ceil of that produces 124 micro-USD for an amount that is exactly 123. Over-reporting money is a defect, not a safe direction.

    from decimal import Decimal, ROUND_CEILING, InvalidOperation, localcontext

def charged_micros(cost_usd: object) -> int | None:
    """Exact micro-USD, rounded up, or an explicitly unknown amount."""

    try:
        # str() first: it yields the shortest decimal that round-trips the
        # value, so Decimal("0.000123") -- not the binary approximation.
        amount = cost_usd if isinstance(cost_usd, Decimal) else Decimal(str(cost_usd))
    except (InvalidOperation, ValueError, TypeError):
        return None
    if not amount.is_finite() or amount < 0:
        return None
    with localcontext() as context:
        context.prec = max(28, len(amount.as_tuple().digits) + 6)
        return int((amount * 1_000_000).to_integral_value(rounding=ROUND_CEILING))

    For an unreadable amount, retain a cost-reporting failure in evidence and report unknown spend. Missing token accounting still requires the case-3 escape.

    Decode the amount exactly, before it becomes a float. The conversion above is only as exact as its input, and str(float) recovers just the digits the float kept — by then 0.0001230000000000000000001 is already 0.000123, and rounding up gives 123 micro-USD instead of 124. A float cannot be repaired after the fact. So read the charge from the raw body:

    import json

body = json.loads(response.text, parse_float=Decimal)
micros = charged_micros((body.get("usage") or {}).get("cost"))

    If your client hands you a decoded object rather than text, take the amount from somewhere exact — a Decimal, an integer, or a decimal string — rather than a float that has already been rounded.

    The duration-parser example supplies an optional cost_reporter(response) callback on its example-owned SDK wrapper. It accepts a function or bound method, so users can calculate a token-price estimate or call their own billing API. Its CostReport explicitly labels estimated versus billed, retains the source, and records the reporter's version in configuration. These are example types; core needs only ordinary ProposalResult/EvaluationResult, Resources, and evidence. A committed report is read back during inspection, without invoking the callback again.

    Never raise an ordinary exception after billing, and never return a bare Failure: both paths reach the adapter with no usage field, so the framework records zero and the charge is lost. This is a framework guarantee about those channels, not something conformance can detect on your behalf.

    Trial and evaluation counts are coordinator-owned; reporting either at the proposer boundary produces typed InvalidOutput. The meeting-notes evaluator rejects response-wrapper counts as a failed measurement, retaining known usage.

    At the proposer boundary, ordinary SDK exceptions become ProposerFailure. Framework failures about durable state, accounting, or run capability escape unchanged: EventStreamConflict, DurableCorruption, InvalidSearchHistory, ExperienceStoreUnavailable, ExecutionAccountingUnknown, and CapabilityError.

    Give an SDK audited pull tools¶

    When an SDK supports custom tools, register a user-owned handler that delegates to context.experience:

    used = []

def search_experience(arguments):
    if context.experience is None:
        raise meta.ExperienceAccessDenied("pull access was not granted")
    observation = context.experience.search(**arguments)
    used.extend(record.ref for record in observation.records)
    return observation

response = my_sdk.run(tools={"search_experience": search_experience})
return meta.ProposalResult(
    candidate=response.artifact,
    derived_from=tuple(dict.fromkeys(used)),
)

    The exact observation API is defined by ExperienceReader. The callback may run in process, or a user-owned RPC service may forward each request to this scoped handler and return its result. The RPC service must not cache or broaden the reader capability. Meta-Evolve adds no generic tool server or agent process.

    Access denial, exhaustion, audit-store failure, and unknown accounting retain their normal semantics because the SDK tool calls the authoritative reader. SDKs without custom-tool support can receive pushed context.bundle data, but that is context injection rather than agent-directed pull.

    The credential-free 06_user_owned_sdk example contains a complete deterministic fake SDK and audited tool callback. An acceptance-gated milestone may own an opt-in real-client experiment, as M8 does for harness validation. There is no generic provider smoke directory: a live script must serve a current gate, add no package dependency, and retain its single authorized outcome honestly.

    Authority and reproducibility¶

    The wrapper may propose candidate content. It cannot choose the evaluator, change the run budget, grant itself experience, edit audit history, or promote a result. External evaluation and durable storage remain the sources of score, accounting, and lineage truth.

    Committed requests, evidence, usage, failures, and artifacts support inspection and replay. Meta-Evolve does not claim that a later external SDK call will regenerate byte-identical output.

    API details: ProposalResult, ProposerContext, and EvidenceDraft.

    Provider migration¶

    The first-party meta_evolve.claude.Claude and meta_evolve.codex.Codex imports, meta-evolve[claude] / meta-evolve[codex] extras, adapters and live fixtures were removed before 1.0 without compatibility shims. Install/authenticate your chosen SDK in your application and call it inside an ordinary proposer or evaluator; follow the current notebook.

    The SDK owns authentication, sessions, tools and provider decoding. Meta-Evolve owns candidate validation, independent evaluation, budgets, history and audited experience. The old provider names remain legitimate in historical evidence, which does not describe current package imports. The historical SDK decision used Usage in rich returns; the 0.2 migration now uses Resources while the coordinator retains logical counts.
