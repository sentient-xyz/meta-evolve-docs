    API examples and edge cases¶

    These small deterministic examples answer questions about the API reference. They use numbers so counting, selection, and failure behavior are easy to see. The duration-parser tutorial provides the complete installation-to-result introduction.

    Run the setup once, then the cells in order. Only an installed meta_evolve package is required; there are no model calls or credentials. The same code is available in reference_cases.py.

    Setup¶

    The proposer adds one to its parent; the evaluator measures the resulting value. The default objective maximizes that measurement as score.

    import meta_evolve as meta
from meta_evolve.domain import EvaluatorFailure


def propose(value):
    return value + 1


def evaluate(value):
    return value

    Seed evaluation and proposal counts¶

    improve(trials=0) evaluates the seed without asking for a revision. trials=2 allows two successor attempts, in addition to the seed. Run.trials() includes the seed record, while Usage.trials counts only successor attempts.

    seed_only = meta.improve(seed=0, proposer=propose, evaluator=evaluate, trials=0)
counted = meta.improve(seed=0, proposer=propose, evaluator=evaluate, trials=2)
for result in (seed_only, counted):
    print([attempt.artifact.value for attempt in result.trials()])
    print("proposals:", result.usage().trials, "evaluations:", result.usage().evaluations)
# Output:
# [0]
# proposals: 0 evaluations: 1
# [0, 1, 2]
# proposals: 2 evaluations: 3

    A failed proposal consumes an attempt without requiring an evaluator call. A failed evaluation still consumes an evaluation. Therefore proposal counts, evaluation counts, and the number of history records need not be equal.

    Ties, regressions, and the selected result¶

    Greedy proposes from the best measured artifact so far. It keeps an earlier successful evaluation on an exact tie. Regressions remain in history, and the seed can remain the selected result.

    selection_cases = {}
for label, measure in (("ties", lambda value: 0), ("regressions", lambda value: -value)):
    result = meta.improve(seed=0, proposer=propose, evaluator=measure, trials=2)
    selection_cases[label] = result
    selected = result.best_trial()
    print(label, "winner:", selected.artifact.value, "score:", selected.metrics["score"])
    print("history:", [attempt.artifact.value for attempt in result.trials()])
# Output:
# ties winner: 0 score: 0
# history: [0, 1, 1]
# regressions winner: 0 score: 0
# history: [0, 1, 1]

    Both successors contain 1: neither replaced the seed as Greedy's parent. best() returns an artifact view with decoded .value; best_trial() returns the producing attempt with its artifact, metrics, evidence, and usage. Neither means “the last attempt.”

    BestOfN always proposes from the seed, even when a successor ranks better. Enabled feedback can still carry earlier observations; independent parent selection does not imply statistically independent model calls.

    One objective on the short path¶

    Pass one Maximize or Minimize as improve(objective=...). A scalar evaluator measures that objective's named metric. Here the evaluator returns distance from three; minimizing error stops as soon as that distance reaches zero:

    def distance(value):
    return abs(3 - value)


closest = meta.improve(
    seed=0, proposer=propose, evaluator=distance, trials=5,
    objective=meta.Minimize("error", satisfy=0),
)
print("selected:", closest.best().value)
print("error:", closest.best_trial().metrics["error"])
print("proposals:", closest.usage().trials, "evaluations:", closest.usage().evaluations)
print("stop:", closest.summary().stop_reason)
# Output:
# selected: 3
# error: 0
# proposals: 3 evaluations: 4
# stop: objective_satisfied

    A mapping or EvaluationResult must instead contain the exact declared metric. A missing measurement is a typed evaluation failure. objective=None keeps the default Maximize("score") with no satisfaction target. If the seed meets an explicit target, search stops after its evaluation, even with trials=0.

    Ordered objectives and satisfaction¶

    Task.objectives defaults to (Maximize("score"),) with no target. A scalar evaluator is valid only with one objective. With several, return a mapping containing every objective's metric; additional metrics are retained without changing the selection rule.

    The first objective controls default ranking and built-in satisfaction stopping. Maximize(..., satisfy=x) accepts values at least x; Minimize accepts values at most x. A target on a secondary objective is not another stopping condition.

    def measure_tradeoff(value):
    return {"quality": value, "cost": value}


tradeoff = meta.run(meta.Experiment(
    task=meta.Task(
        evaluator=measure_tradeoff,
        objectives=(meta.Maximize("quality", satisfy=2), meta.Minimize("cost", satisfy=0)),
    ),
    seed=0,
    proposer=propose,
    search=meta.Greedy(max_trials=3),
))
print("primary winner:", tradeoff.best().value)
print("lowest cost:", tradeoff.best("cost").value)
print("proposals:", tradeoff.usage().trials)
print("stop:", tradeoff.inspect().overview.stop_reason)
# Output:
# primary winner: 2
# lowest cost: 0
# proposals: 2
# stop: objective_satisfied

    The seed already meets the secondary cost target, but the run continues until quality reaches two. Querying best("cost") afterward ranks the retained history by that declared objective; it does not rerun search or change its decisions. This declaration does not request Pareto or joint multi-objective optimization.

    Tighten one budget dimension¶

    Budget controls allowed work independently of search. run(experiment) uses the task budget. In a supplied budget=, omitted or None fields inherit task ceilings; supplied finite limits cannot exceed them.

    When the task bounds both proposals and evaluations, passing only Budget(evaluations=2) tightens evaluations and retains the trial ceiling. Inspect the resolved budget to see both limits:

    task = meta.Task(evaluator=evaluate, budget=meta.Budget(trials=4, evaluations=5))
experiment = meta.Experiment(task=task, seed=0, proposer=propose, search=meta.Greedy(4))
tighter = meta.Budget(evaluations=2)
limited = meta.run(experiment, budget=tighter)
print("retained proposal ceiling:", limited.inspect().declaration.effective_budget.trials)
print("proposals:", limited.usage().trials, "evaluations:", limited.usage().evaluations)
print("stop:", limited.inspect().overview.stop_reason)
# Output:
# retained proposal ceiling: 4
# proposals: 1 evaluations: 2
# stop: budget_exhausted

    Budget() retains every task limit. Explicit widening, such as Budget(evaluations=6) against this task's five-evaluation ceiling, raises ValueError before component calls or committed run facts. See the migration notes for previously rejected partial overrides.

    Preset defaults follow the allowance¶

    Greedy, BestOfN, Population, Specialists, and TreeSearch inherit finite effective Budget.trials when max_trials is omitted or None. Without that ceiling, they use 20, or 100 for TreeSearch. An explicit integer is a voluntary stop. improve(trials=...) keeps its integer-only default of 20.

    allowance = meta.Task(evaluator=evaluate, budget=meta.Budget(trials=25))
for search in (meta.Greedy(), meta.Greedy(max_trials=20)):
    result = meta.run(meta.Experiment(task=allowance, seed=0, proposer=propose, search=search))
    print("proposals:", result.usage().trials, "evaluations:", result.usage().evaluations)
# Output:
# proposals: 25 evaluations: 26
# proposals: 20 evaluations: 21

    See Migrate to 0.2 to retain earlier work amounts.

    Proposer arguments and feedback¶

    A plain proposer accepts (parent) or explicitly requests ProposerContext with (parent, *, context). Ordinary optional arguments retain their Python defaults:

    def scale_candidate(parent, scale=2):
    return parent * scale


scaled = meta.improve(seed=1, proposer=scale_candidate, evaluator=evaluate, trials=1)
print(scaled.best().value)
# Output:
# 2

    Request framework state explicitly:

    def advance(parent, *, context):
    return parent + context.step


advanced = meta.improve(seed=0, proposer=advance, evaluator=evaluate, trials=2)
print(advanced.best().value)
# Output:
# 3

    To receive feedback, pass context=RecentAncestors(...) to improve() or Experiment and accept the keyword-only context in the proposer. Read context.evidence.latest(kind) or the bundle's bounded .rendered text. Pushed feedback is off by default; recording evidence alone does not enable it. PullAccess separately supplies an audited reader as context.experience. Follow the feedback guide for a complete example. The migration guide covers existing positional callbacks and registered histories.

    This bounded loop uses exact evaluator evidence to propose the next value. Two records hold one evidence item and its evaluation in this example; a different evaluator may need a larger bound. One rendered character deliberately demonstrates that structured evidence remains available when text is clipped.

    def feedback_score(value):
    return meta.EvaluationResult(metrics={"score": value}, evidence=(
        meta.EvidenceDraft(kind="feedback", data={"value": value}),
    ))


def feedback_revision(parent, *, context):
    item = context.evidence.latest("feedback")
    if item is None:
        return parent
    return meta.ProposalResult(candidate=item.data["value"] + 1,
                               derived_from=(item.ref,))


feedback_run = meta.improve(
    seed=0, proposer=feedback_revision, evaluator=feedback_score, trials=6,
    context=meta.RecentAncestors(max_records=2, max_chars=1),
)
print("selected:", feedback_run.best().value)
print("proposals:", feedback_run.usage().trials,
      "evaluations:", feedback_run.usage().evaluations)
# Output:
# selected: 6
# proposals: 6 evaluations: 7

    latest() raises meta_evolve.errors.ContextDisabled with pushed context off; an enabled policy with no selected match returns None. Check .enabled when feedback is an optional dependency. The experience guide explains selection order, provenance, and upgrading durable histories.

    Plain values and result records¶

    A proposer can return a candidate directly; an evaluator can return a scalar or metric mapping. Use ProposalResult and EvaluationResult when you also need observations, usage, or typed failures. Their maps are frozen on construction.

    def propose_with_usage(parent):
    return meta.ProposalResult(
        candidate=parent + 1,
        hypothesis="A larger value should score higher.",
        usage=meta.Resources(tokens=5, spend_micros=None),
    )


def evaluate_with_evidence(value):
    return meta.EvaluationResult(
        metrics={"score": value},
        evidence=(meta.EvidenceDraft(kind="measurement", data={"value": value}),),
    )


recorded = meta.improve(
    seed=0, proposer=propose_with_usage, evaluator=evaluate_with_evidence, trials=1,
)
selected = recorded.best_trial()
print("value:", selected.artifact.value, "score:", selected.metrics["score"])
print("evidence:", selected.evidence[0].data["value"])
print("tokens:", recorded.usage().tokens, "spend:", recorded.usage().spend_micros)
# Output:
# value: 1 score: 1
# evidence: 1
# tokens: 5 spend: None

    The token amount above is a declared fixture, not measured provider activity. Rich results take Resources, containing tokens, billed micro-USD, and elapsed seconds. The engine owns counts and records Usage. Passing the old Usage value to a rich result raises at construction.

    Forward nested resources¶

    Project inner.usage().resources, then add the evaluator's own costs once. Here each outer evaluation runs one inner proposal reporting five tokens and unknown spend, then adds two tokens of its own. Inner counts remain inner:

    def evaluate_procedure(value):
    inner = meta.improve(seed=value, proposer=propose_with_usage, evaluator=evaluate, trials=1)
    return meta.EvaluationResult(
        metrics={"score": inner.best().value},
        usage=meta.Resources(tokens=2) + inner.usage().resources,
    )


nested = meta.improve(seed=0, proposer=propose, evaluator=evaluate_procedure, trials=1)
print("outer proposals:", nested.usage().trials, "evaluations:", nested.usage().evaluations)
print("tokens:", nested.usage().tokens, "spend:", nested.usage().spend_micros)
# Output:
# outer proposals: 1 evaluations: 2
# tokens: 14 spend: None

    Unknown spend and monetary ceilings¶

    Resources(spend_micros=0) means known free work. None means an unknown bill; adding an unknown amount makes the aggregate unknown. Estimates belong in evidence. One micro-USD is one millionth of a US dollar.

    With no monetary ceiling, the preceding run can evaluate its successor. Under a monetary ceiling, an unknown proposal charge prevents further work:

    unknown_spend = meta.run(meta.Experiment(
    task=meta.Task(evaluator=evaluate_with_evidence, budget=meta.Budget(spend_micros=100)),
    seed=0,
    proposer=propose_with_usage,
    search=meta.Greedy(2),
))
print("states:", [attempt.state for attempt in unknown_spend.trials()])
print("candidate retained:", unknown_spend.trials()[-1].artifact.value)
print("best measured:", unknown_spend.best().value)
print("stop:", unknown_spend.inspect().overview.stop_reason)
# Output:
# states: ['evaluated', 'unevaluated']
# candidate retained: 1
# best measured: 0
# stop: accounting_unavailable

    The proposed value is retained, but was never evaluated. It cannot replace the measured seed. If the evaluator instead reports unknown spend, its completed measurement is retained and further work stops.

    Resource reports are checked after calls return. A reported monetary overrun is charged and recorded as a typed ResourceExhausted failure. A zero spend ceiling permits known free work. These ceilings neither interrupt an in-flight SDK request nor guarantee a provider hard spending cap. See evaluation and budgets for accounting details.

    No successful evaluation¶

    Failures such as EvaluatorFailure, ProposerFailure, and InvalidOutput are data from meta_evolve.domain, not exceptions to raise. Return them directly, or attach one to a result record. A failed proposal omits candidate; a failed evaluation omits metrics. Contradictory records raise ValueError.

    def unavailable(value):
    return meta.EvaluationResult(failure=EvaluatorFailure(message="grader unavailable"))


failed = meta.improve(seed=0, proposer=propose, evaluator=unavailable, trials=0)
try:
    failed.best()
except meta.NoSuccessfulEvaluation:
    print("No successful evaluation")
print("state:", failed.trials()[0].state)
report = failed.summary()
print("evaluations:", report.evaluation_count)
print("rankability:", report.rankability)
print("score:", report.primary_score, "lineage:", report.winning_lineage)
print("lifecycle:", report.lifecycle)
# Output:
# No successful evaluation
# state: evaluation_failed
# evaluations: 1
# rankability: unrankable
# score: None lineage: ()
# lifecycle: complete

    NoSuccessfulEvaluation is an exception: best(), best_trial(), and default-winner lineage() raise it when nothing ranks. summary() returns state, absent score, and recorded costs; trials(), usage(), and inspect() also remain available. See the summary migration guide.

    Invalid output and ordinary exceptions inside a proposer or evaluator become typed outcomes. Declaration errors, unsupported capabilities, and infrastructure faults can raise instead of returning a Run; they are not candidate scores.

    Retained history and resume¶

    Passing Storage.durable(path) to improve() or local run() saves history. Reopen it with Run(run_id, storage) to inspect facts without executing components. Resuming unfinished work additionally requires a supported mode and registered, reconstructible components. Follow save and reopen and recovery for those separate workflows.
