    Meta-Evolve Programming Model¶

    The smallest useful mental model¶

    Start with an artifact, a function that proposes revisions, and an independent function that measures them. To run these cells, first run Start here. It defines meta, SEED, propose, evaluate, and load_parser without an SDK or credentials. With those definitions, the smallest run declaration is:

    The first run
    result = meta.improve(
    seed=SEED,
    # This example returns a handwritten correction.
    # Replace it with a function that asks an agent or LLM for new candidates.
    proposer=propose,
    evaluator=evaluate,
    trials=1,
)

    improve() assembles a task, an experiment, and bounded Greedy search. It evaluates the seed, tries up to trials proposed revisions, and returns a Run containing the history. An attempt need not improve the score; the seed can remain the selected result.

    The keyword-only signature is improve(*, seed, proposer, evaluator, trials=20, storage=None, random_seed=0, objective=None, context=None) -> Run.

    objective accepts one Maximize or Minimize; None uses Maximize("score") without a satisfaction target. A scalar evaluator measures the selected objective's metric. A mapping or EvaluationResult must contain that exact metric; missing measurements become typed evaluation failures. A seed meeting an explicit target stops after one evaluation with no proposals, even at trials=0; an unsatisfied seed at that limit stops at the proposal allowance.

    context accepts an explicit bounded policy, such as RecentAncestors. None and NoMemory() supply no pushed feedback. A proposer requests (parent, *, context) and reads context.evidence.latest(kind) from the selected bundle; disabled access raises ContextDisabled, while an enabled policy with no match returns None. This setting does not enable pulled experience. See the single-objective example and feedback lesson.

    These optional keywords preserve existing calls and lower to Task.objectives and Experiment.context. trials remains a nonnegative integer (not None or a boolean); storage defaults to isolated memory and randomness to seed zero. Malformed declarations fail before evaluation or committed run facts. Saving local history does not make a run resumable.

    The objects below let you configure and control that same loop. Each execution starts from the same seed in separate default in-memory storage; it does not continue the previous run.

    Task: define what better means¶

    A Task defines the evaluation contract for an artifact. It requires an evaluator, which measures a candidate, and uses objectives to interpret those measurements. The default objective maximizes score, without a satisfaction threshold. Here the evaluator checks six parser inputs:

    task = meta.Task(evaluator=evaluate)

    You can also declare the artifact type, evaluation environment, and budget ceilings on the task. The task is reusable across seeds, proposers, and search strategies; constructing it declares the rules without running an evaluation. The evaluator owns the checks and expected answers. Proposed artifacts cannot revise that contract. See evaluation and limits to change measurements, objectives, or ceilings.

    Experiment: choose how to search¶

    An Experiment combines a task with a seed and a proposer. Its search policy chooses which version to revise and when to stop. Bounded Greedy search is the default; here we give it the same allowance as the first run:

    experiment = meta.Experiment(
    task=task,
    seed=SEED,
    proposer=propose,
    search=meta.Greedy(max_trials=1),
)

    The declaration is immutable and starts no search. Optional context and experience settings control what prior observations a proposer can receive. Recording a score alone does not send it as feedback; the feedback guide shows that configuration.

    Pass the declaration to run() to execute until search stops and receive the recorded result:

    expanded_result = meta.run(experiment)

    Session: control execution¶

    A Session is the active execution handle for an experiment. Use Session.start(experiment) when you want to inspect progress between decisions. For local execution, the seed is already evaluated when start() returns. Each step() completes one search decision and returns its immutable view. A decision can attempt a revision, update an archive, or stop; a step does not promise a better candidate.

    session.run provides recorded results: best_trial() gives the selected attempt, and usage() reports work consumed.

    with meta.Session.start(experiment) as session:
    print("Evaluations after start:", session.run.usage().evaluations)
    first_decision = session.step()
    score = session.run.best_trial().metrics["score"]
    print(f"After one step: {score:.0%}")
    print("Evaluations so far:", session.run.usage().evaluations)
    while not session.stopped:
        session.step()
    paced_result = session.run
# Output:
# Evaluations after start: 1
# After one step: 100%
# Evaluations so far: 2

    run(experiment) completes this lifecycle for you. Stepping gives you control over when execution advances; the declared search still chooses the decisions. The experiment and effective budget stay fixed for the session. Leaving the with block closes this execution handle; session.run remains inspectable. Leaving early does not finish the remaining search.

    Run: inspect what happened¶

    A Run gives you access to recorded results and history. improve() and run() return it after execution stops; session.run also lets you inspect work already recorded while a session is active. Reading its methods does not advance search.

    You want to know… Use
    Which value was selected? best().value
    What happened, and which versions led to the selection? trials() and lineage()
    What is the current state and work consumed? summary() and usage()
    Why did attempts succeed or fail? inspect() 
    scores = [
    f"{attempt.metrics['score']:.0%}"
    for attempt in paced_result.trials()
]
print(scores)
selected = paced_result.best().value
parse_seconds = load_parser(selected)
print("4m:", parse_seconds("4m"))
# Output:
# ['33%', '100%']
# 4m: 240

    These are the same measured results as the original improve() call and the expanded run() call. Failed attempts remain inspectable; when no evaluation succeeds, best() raises NoSuccessfulEvaluation. Use result inspection to examine that case.

    Summaries and comparisons¶

    Run.summary() reads one validated snapshot of an existing run. Its frozen RunSummary reports:

    Field Meaning
    lifecycle complete when a stop is committed; otherwise incomplete
    rankability rankable when a successful measurement can be selected; otherwise unrankable
    stop_reason Recorded stop reason, or None while incomplete
    primary_score Selected primary measurement, or None when unrankable
    winning_lineage Decoded causal lineage, or an empty tuple when unrankable
    evaluation_count All committed evaluations, including failures and the evaluated seed
    primary_objective, baseline_score Primary objective and successful seed measurement; failed or pending seed measurements are absent
    failure_count Distinct attempts with a committed typed proposal/evaluation failure, including a failed seed
    storage_is_durable, storage_location Durability and optional location of the handle at capture; a custom durable store may have no path
    capabilities Recorded execution mode and resume capability, without verifying current compatibility or permission

    The seed can win, zero and negative scores remain measurements, and a stopped run can still be unrankable. Usage, declarations, experience totals, decoded seed, and component provenance remain available in every state. Pending work does not contribute a guessed charge. Summary, usage, and inspection also work before a distributed seed evaluation completes. Missing runs raise RunNotFound; invalid history retains its typed integrity error.

    Capture while storage is open: snapshot = result.summary(). print(snapshot) produces bounded text; a notebook displays escaped HTML when snapshot is its cell's final expression. Both remain usable after storage closes or disappears. They omit decoded artifact values, evidence bodies, and manifests. Programmatic fields retain their full values; a frozen summary does not make arbitrary decoded custom objects deeply immutable.

    The report separates completion, successful measurement, and improvement. It compares the baseline and selected scores in the primary objective's direction; a tie is no improvement, and an absent measurement means improvement is unavailable. Proposal counts exclude the seed; evaluation counts include it when evaluated. Typed failures keep their costs. Task spend and context/pull usage remain separate, and unknown spend remains unknown.

    History is reported at capture: memory-only history is not saved durably, and a saved history does not grant resume permission. Recorded resume support is not a current compatibility check; a complete run has no continuation pending. repr(result) shows its identifier without I/O. Explicit queries, including another summary(), still require accessible storage and retain their real errors. See result inspection and storage lifetime.

    best(), best_trial(), and default lineage() still require a successful evaluation. compare(other) requires one on each side, reading left then right, before applying its existing declaration checks. Incomplete runs may be compared if both rank; two missing scores never constitute a tie. Each side uses one validated snapshot, without promising an atomic read across independent stores.

    Direct RunSummary construction requires keyword-only lifecycle, rankability, and stop_reason; existing positional fields keep their order. The six report metadata fields above are optional keywords defaulting to None (unknown). Supplied facts participate in record equality; an old-style manual summary can therefore differ from a fully populated captured summary. See the summary migration guide for constructor invariants and CLI behavior. A returned summary certifies neither improvement nor resumability.

    Choose what to change¶

    Change you want Where it belongs
    Measure candidates differently improve(evaluator=...) or Task.evaluator
    Prefer one metric or set a target improve(objective=...) or Task.objectives
    Supply bounded feedback improve(context=...) or Experiment.context
    Generate different revisions Experiment.proposer
    Choose different parents or a proposal allowance Experiment.search
    Pause between decisions and inspect progress Session.step() and session.run

    To change a declaration, construct a new value, reusing the components that still apply. Search demonstrates reusing a task and proposal rules with another policy. The routing lesson applies the same callable path to instruction text.

    Execution contracts¶

    Evaluation, budgets, and permissions remain outside candidate authority. External SDKs are user-owned callables; Use your model SDK shows their request wiring, execution limits, and accounting. No first-party provider adapter is shipped. Simulated tutorial responses are not live-provider evidence.

    For existing callers, the source-compatible declaration-keyword spelling of run() remains available. New examples use the typed declaration. The pre-1.0 release policy supersedes the earlier through-1.x promise; this spelling is retained in the selected 0.2 scope:

    Supported keyword form · with the same declared experiment
    result = meta.run(
    task=experiment.task,
    seed=experiment.seed,
    proposer=experiment.proposer,
    search=experiment.search,
    context=experiment.context,
)

    Experiment owns the eight declaration fields and defaults. Storage, mode, and a narrowing call-level budget are execution overlays on run(), never experiment fields. In a supplied budget, omitted or None dimensions inherit task ceilings. Finite values may tighten or introduce ceilings; exceeding a finite task ceiling raises ValueError before work starts. Budget() preserves all task ceilings. See the budget override example.

    The returned Run supports inspection, trials, lineage, evidence, usage, failures, summaries, and comparisons. Rich ProposalResult and EvaluationResult reports take immutable Resources with tokens, billed spend, and elapsed work. Trial/evaluation fields and the old author Usage value are rejected. Plain candidate/scalar/mapping returns remain direct. Run.usage() returns Usage, including engine-owned counts; forward nested work with inner.usage().resources. Structural PatchResult, process and durable domain records retain Usage.

    Resources.spend_micros and recorded Usage.spend_micros accept a billed integer or None for unknown; its default 0 describes known free work. Unknown totals remain unknown, and monetary ceilings stop further work when spend cannot be verified. Estimates remain evidence. See evaluation and budgets. Safe frozen-payload presentation, direct-parent diff rules, and exact current canonical-payload-v1 bytes are specified by the browser guide.

    In local and durable-local execution, run() exhausts the synchronous Session. Session fixes components and authority at start. Each step() commits one decision or completes one owed by recovery; it accepts no injected decision. Bootstrap is complete before Session.start() returns and is not a policy step. Distributed execution uses a different pacing boundary; see execution profiles.

    Durable storage has two independent axes: is_durable means committed facts live on durable media, while is_read_only means this handle has no commit or execution authority. Storage.durable(path) is durable and writable; Storage.read_only(path) is durable and read-only. Storage.run_version(id) returns the maximum committed event sequence, or 0 when that well-formed id has no events. The latter is a polling result, not authoritative run loading: opening a required missing run still raises RunNotFound.

    Reopen saved history¶

    open_run(path, *, run_id=None, registry=None) owns a read-only storage handle and yields the existing Run in a with block. path is the directory passed to Storage.durable(). An explicit RunId or ID string selects only that run; a missing selected run raises RunNotFound without fallback. ID strings must be nonempty and have no outer whitespace. Other ID types and invalid registries raise TypeError; malformed strings raise ValueError.

    With run_id=None, an empty store raises RunNotFound, a single run is selected, and multiple runs raise RunSelectionRequired. Its run_ids tuple lists available identities lexically, not chronologically. Selection occurs once; later additions do not retarget the handle. Argument validation, opening, and authoritative history validation happen on context entry. Incomplete and unsuccessful histories remain readable; missing, corrupt, and incompatible storage retain their existing typed errors.

    Storage closes on normal exit or error. Capture summary(), inspect(), or usage() inside the block for use afterward; the live Run still requires open storage for queries. Queries can observe later commits, while each summary or inspection captures one validated frontier. registry= supplies custom artifact codecs for decoded queries; entry validation and usage() do not require those codecs. A missing codec raises CapabilityError when decoding is requested. Reopening neither executes components nor resumes or migrates a run. Committed history is unchanged; SQLite may maintain WAL sidecars. See the durability guide for lifetime and storage details.

    Selected evidence¶

    context.evidence.latest(kind) returns the last matching evidence in the already selected bundle's canonical order. Its immutable item exposes data, kind, uri, ref, logical_step, and event_sequence; ref can be cited in an explicit ProposalResult.derived_from. Same-step matches follow bundle order. Both proposer and evaluator evidence qualify; a label does not certify authorship, success, or a relationship to the current parent.

    context.evidence.enabled reports the pushed-policy declaration. None and NoMemory() are disabled: calling latest() raises ContextDisabled, a CapabilityError, at use rather than repeatedly failing proposals. An enabled selection with no matching record returns None. Use an explicit enabled check when feedback is optional. Manually constructed ProposerContext values must supply context_policy to enable this accessor; bundle contents/reason are not proof of a declaration. Separately declared pull access does not enable it.

    RecentAncestors retains the newest accessible ancestor records within max_records, returning them in canonical order. AncestorsOnly@1 still retains the oldest records, and BestSibling keeps its existing ranking. No preset promises matching evidence under every bound. context.evidence.truncated mirrors the committed aggregate flag: omitted records or clipped rendering. max_chars bounds rendered text, not item data. Lookup performs no I/O, grants no access, and never merges pull observations. See the feedback lesson and source/migration implications.

    Proposer callback arguments¶

    Plain callbacks receive the parent positionally. Only a named keyword-only context requests ProposerContext, even when that keyword has a default. Ordinary defaults such as factor=2 remain Python configuration. Variadics alone do not request framework inputs.

    def propose(parent, factor=2):
    return parent * factor

def propose_with_context(parent, *, context):
    return parent + context.rng.choice((-1, 1))

    Preparation inspects and binds once, before seed evaluation or committed facts. An additional positional context, unbound required arguments, or an uninspectable plain callback raises TypeError. A body that raises TypeError is invoked once and normalized as a proposer failure; it is never retried to guess a signature. Local bound methods, partials, and callable instances follow their effective signatures; durable registration still requires source-verifiable module-level functions. Structural .propose(parent, context) objects retain their explicit port and parent-only convenience. See the callback migration guide for route precedence, optional aliases, wrappers, and historical resume consequences.

    Canonical public surface¶

    This is the canonical contract for the shipped public API available from the current package. The generated API reference owns signatures and parameter details; the guides teach task-oriented usage.

    The reference groups root exports by task. Root imports are public; kernel records remain internal unless a guide describes an extension protocol.

    The constructible harness family stays under meta_evolve.harness: HarnessArtifact, HarnessMutation, MutationSurface, TextParam, PolicyParam, MutationApplication, portable repository episodes, comparison views, and export views. Only compare_harnesses, export_harness, and load_harness are root conveniences.

    The neutral MutationApplication and MutationSurface contracts live under meta_evolve.mutation; harness keeps compatibility re-exports. The data-only meta_evolve.policy family contains PolicyArtifact, its two fixed surfaces and mutation, CandidatePolicy, portable episodes/suites, captured outcomes/evaluations, and comparison views. compare_policies is the single root convenience.

    Execution profiles¶

    local accepts live Python components and defaults to a separate in-memory store. Local execution does not itself isolate untrusted code; see the source execution boundary. durable-local requires durable storage plus registered, reconstructible components and records enough identity to resume honestly through Session.resume() or resume(). Persisting a local run keeps history; it does not make its callables resumable. distributed adds a durable work table and uses Session.drive() instead of step(). Select worker processes explicitly: drive(execution=WorkerProcesses(n, module)) spawns them for this run, and drive(execution=WorkerHost(address, key_file)) accepts workers an operator starts, each admitted by a handshake that proves a shared key and the same build. Malformed MACs refuse their connection; admission prevents distinct live processes from sharing a worker identity. An external worker retains an unanswered completed result across connection loss and resubmits it for a store-authoritative answer. Without execution= the work runs on a helper thread in this process, one call at a time. A dispatcher that dies leaves its work claimable again, and resuming re-admits workers and finishes the run.

    Session.drive(lease_seconds=60) accepts a lease duration of at least 10 seconds. The dispatcher renews the lease while the component runs. A call may continue after its lease or drive is lost, and recovery may execute the work again. Execution is at least once; acceptance is at most once, enforced by leases, dispatcher epochs and atomic commits. Independent stores remain independent even when their experiments produce the same run ID. See current status for supported scope.

    Authority and failure boundary¶

    Candidates may propose artifact content. They cannot change the evaluator, effective budget, permissions, hidden data, audit history, or promotion rule. Invalid output, proposer/evaluator failure, timeout, exhaustion, policy violation, and infrastructure failure remain typed, inspectable outcomes. A failure with no valid measurement is never ranked as a low score.

    Harness candidates receive a second, trusted check after codec encoding and before artifact creation. The built-in harness codec compares the encoded successor with its one parent and rejects changed component references, interfaces, parameter names or types as PolicyViolation; malformed and no-op transitions are InvalidOutput. Wrapper-side mutation helpers are convenience, not authority.

    Bounded list_source_paths, read_source, and diff_source operate on exact, prior same-task/run occurrences. Successful observations may be cited in proposal derivation. PatchProposer can project a bounded committed manifest through adapter-only GitHistoryView; its callback receives meta_evolve.ports.WorkspaceSession. These observations do not widen candidate authority or change artifact identity. See audited pull for access and charging rules.

    meta.PatchProposer(
    edit,
    history=meta_evolve.adapters.GitHistoryView(
        max_ancestors=4,
        max_archive_members=2,
        max_chars=128_000,
    ),
)

    All bounds are required non-negative keywords. history=None preserves prior identity and behavior. In a history-enabled callback, defaulted ProposerContext.workspace contains root, the complete controlled subprocess environment, and the committed history manifest.

    Composable policy pieces¶

    The search presets share the task's external allowance. For Greedy, BestOfN, Population, Specialists, and TreeSearch, omitted/None max_trials inherits finite effective Budget.trials, otherwise using 20 (100 for TreeSearch). Explicit integers are voluntary stops. The resolved integer is recorded once; replay never re-inherits. improve, BestOfK, functional search, and custom/candidate policies retain their own limits. See migration for changed defaults.

    For bounded single-parent refinement, an author may declare the parent choice without receiving kernel state or constructing trials:

    @meta.search(max_trials=20)
def incumbent_refinement(search):
    return search.expand(search.incumbent or search.seed)

    The callback sees only opaque seed and optional incumbent occurrence handles, immutable declared configuration, expand(), and stop(). The adapter owns proposer binding, the unit budget, the objective and exhaustion envelope, named trial randomness, and durable explanation. Behavior-affecting configuration belongs on the decorator; closure capture is rejected because it would be invisible to run identity. Population-shaped actions and archive decisions remain on the full SearchProgram.next() extension protocol.

    Specialists and per-metric retention¶

    Specialists (meta_evolve.policies.Specialists, not a root export) retains one winning artifact occurrence per configured metric and expands a uniformly sampled metric's owner, weighting parent selection by how many metrics an occurrence owns. It is GEPA-style per-key frontier evolution, not a Pareto archive. See the search guide.

    TreeSearch and value-directed tree allocation¶

    TreeSearch (meta_evolve.policies.TreeSearch, not a root export) reconstructs one node per materialized artifact occurrence from durable history. It widens a node with a new child while child_count < ceil(sqrt(node_visits)) and otherwise descends by normalized best-descendant UCT, breaking exact ties by ascending artifact occurrence ID. See the search guide.

    The simplicity test¶

    A common first run should remain improve(seed, proposer, evaluator, trials). A common expansion should remain one Task, one Experiment, and one meta.run(experiment) call. New internal protocols must not make that public story larger.

    The small path accepts individual declarative values with obvious defaults and existing owners. Every additional keyword needs an explicit requirement and acceptance gate. The selected extensions are one objective and pushed context. Multiple objectives, artifact/environment declarations, budgets, custom search, registry, execution mode, and pulled experience use the expanded path. A budget on improve() would require a separate decision about its interaction with trials; there is no generic options bag.
